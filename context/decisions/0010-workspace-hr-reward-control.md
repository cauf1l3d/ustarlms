# ADR 0010 — Work previews, HR operations and reward controls

2026-09-30. Implemented for review; deployment is a separate step.

Recipients come from the actor's existing organization scope. Three dependent selectors resolve department, position and the actual employee against current organization_identity. A POST validates all three again. Service/test/inactive accounts and broken assignments are excluded; no name-based identification of Patimat is performed. HR rights are assigned to the existing ustar_hr role, not to a guessed account. HR can read the company, request staffing, assign repeat courses in the existing learning scope and grade assessments. Direct-manager grade approval and registration approval keep their current separate authorization rules.

Home contains independent active task and checklist lists. Inline report forms call the existing POST task commands with versions, sesskey and full mandatory-field/photo validation. No GET mutates task state. Read-only view-as never renders writable quick forms. KPI sums accepted assigned work with an elapsed deadline; private notes and cancelled work are excluded. Personal KPI resets affect the personal counter; management analytics retain the historical period totals.

Reward control belongs to the explicitly requested emheadabdurahman account only while it also retains site-admin or local/ustar:admin authority. The username alone cannot grant authority. Rules are versioned, effective from a future second; old event timestamps select old rules. Course/activity XP remains a read model of Moodle completion; game XP is frozen in mastery; route and work grants freeze amounts in an append-only reward table. USCOIN remains in the existing locked ledger, never a second wallet. Course/activity/game events do not separately issue coins; coins are configured for route points and accepted tasks/checklists. A zero-value grant still gets an idempotency marker.

Reset has a server-side preview token bound to actor/target/units/before values, ten-minute expiry, CSRF and an explicit second POST. USCOIN reset is a compensating debit, with an expected balance check under the wallet lock. XP/KPI reset starts a new personal counting period; it never deletes course completions, attempts, tasks, mastery or awards. Old source events are not replayed. Reset records preserve who, when, why and previous values. Same-second completions belong to the old personal counting period. Competition standings and earned badges are outside this reset.

Migration adds two tables and explicit HR capabilities. The taskescalation migration now registers capabilities before assigning them. The DB harness additionally installs exact PR63, creates/checks corporate roles, upgrades without operator preregistration and repeats the upgrade. No production deployment or destructive database recovery is performed by this change.
