# Понятные ответы Telegram и важные автоалерты — 18 октября 2026

Владелец подтвердил, что бот отвечает. Этот выпуск исправляет представление данных и готовит нативную кнопку Mini App. Пакет устанавливается поверх существующего пульта, без повторного ввода токена, пароля, CA или подписки Xray. Предыдущие failure receipts сохранены; новый факт ответа — в [owner receipt](../context/runtime/console_bot_working_20261018.json).

## Что изменилось

| Кнопка / команда | Что показывает |
| --- | --- |
| 📊 Сводка · `/status` | Академия, сервер, данные и мониторинг; отклонения отдельно от неподключённых источников |
| 💻 Ресурсы · `/metrics` | CPU, свободная/общая RAM, swap, uptime, SSD/HDD и inode, SMART каждого диска, NTP |
| 🎓 Академия · `/academy` | Контейнеры, локальный HTTP/время HEAD, подключения/ожидания/размер PostgreSQL, последний успех cron и очередь |
| 💾 Бэкапы · `/backup latest` | Время, возраст, размер, имя и SHA256 последней завершённой копии; ссылка на защищённую загрузку |
| 🧪 Стенды · `/labs` | Понятное состояние контроллера, автоостановка или её отсутствие; доступность Moodle отдельно не заявляется |
| 🔔 Алерты · `/alerts` | Текущие отклонения, состояния правил CPU/RAM/OOM, очередь/сбои доставки и пороги |
| 🖥 Пульт · `/panel` | Адрес и условия доступа; после opt-in — нативная кнопка Web App |

Время отображается в МСК, объёмы — МиБ/ГиБ/ТиБ. Состояние «В норме» отличается от уведомления «ВОССТАНОВЛЕНО». Устаревшие/неполученные показания не превращаются в нули. Частичный SMART, например отсутствие SSD197/199, объясняется явно. Bot не выполняет новый бэкап по запросу metadata и не пересылает архив/ключ. SHA256 в карточке взят из проверенного receipt создания; повторного чтения гигабайтного архива на каждый запрос нет. Успешная копия не равна принятому восстановлению.

Первый ответ отправляется в том же цикле polling. До четырёх команд за10с обрабатываются в одном batch; лимит, allowlist actor+private chat и replay offset сохраняются. Отправка идёт через прежнюю durable SQLite очередь с retries. Если Bot API отверг разметку кнопок, текст повторяется один раз без кнопок; неоднозначная ошибка соединения не вызывает такого немедленного повтора.

## 2. Обновить пульт

Запустить целиком в SSH под aduk. Updater кратко останавливает службы пульта; контейнеры Академии не перезапускает. Занятые queued/running операции блокируют обновление. Сравнивает unit files, сохраняет старый venv, проверяет установку и откатывает venv при ошибке. Токен, proxy, outbox, пользователи/пароли/CA/TOTP остаются в текущих отдельных хранилищах.

```bash
sudo -v
sudo -n bash <<'USTAR_BOT_UPDATE'
set -Eeuo pipefail
umask 077
USTAR_RELEASE=$(mktemp -d /root/ustar-console-bot-b275f899.XXXXXXXX)
install -o root -g root -m 600 \
  /home/aduk/ustar-console-b275f899.tar.gz "$USTAR_RELEASE/release.tar.gz"
printf '%s  %s\n' 592a58d1d60a6c3720e075b62e11a7cb31fe4d287eb2d159a2eed116cba1d148 \
  "$USTAR_RELEASE/release.tar.gz" | sha256sum --check --strict -
tar --extract --gzip --no-same-owner \
  --file "$USTAR_RELEASE/release.tar.gz" --directory "$USTAR_RELEASE"

  b275f899125b3ecf294c2dde9041e185972a3f51

```

Ожидается `CONSOLE_UPDATE=PASS`. При `ROLLED_BACK` или другом отказе сохранить безопасный код результата и разобраться с причиной. Повторный Telegram setup и установка Xray для этого обновления не нужны.

## 3. Проверить ответы и автоалерты

```bash
sudo systemctl is-active ustar-console-notify.service ustar-telegram-egress.service
sudo /opt/ustar-console/venv/bin/ustar-console-accept
```

В личном чате своему боту отправить `/start`, затем нажать семь кнопок. Команды можно отправлять отдельно:

```text
/status
/metrics
/academy
/backup latest
/labs
/alerts
/panel
```

Обычный polling —10с; очередь может добавить задержку. Проверить читаемые значения, МСК, кнопки и совпадение с пультом. Неподключённые источники не выдаются за проверенные; stopped-стенд не требует TTL. Статический список `remaining` установочного acceptance сам по себе не учитывает ручное подтверждение получения сообщения: реальный ответ бота проверяет владелец.

После старта notifier важные автоалерты действуют постоянно, дополнительных таймеров включать не требуется. Это существующие правила с улучшенным содержанием: событие, текущие значения, порог/выдержка, причина, время снимка и действие. Нет штатных рассылок «всё хорошо».

Повтор аварии —30мин, warning/NoData —4ч. Восстановление —30с стабильного результата, внешний источник —60с. Ранее отправленная проблема не отправляется немедленно заново только из-за обновления текста. Maintenance от управляемого backup/restart подавляет только cron/локальный HTTP/контейнеры до45мин; OOM и recovery marker не подавляются.

Серверный бот не может отправить сообщение после потери питания, сети server1 или своего процесса. Для этого остаётся отдельная установка независимого observer на другом узле с собственной связью/очередью. В этом выпуске она не заявляется установленной. CI проверяет правила и очередь на fixtures; реальные аварии на проде для теста не создаются.

## 4. Нативное открытие пульта в Telegram

Поддерживается кнопка Telegram `web_app`, которая открывает существующий адаптивный пульт внутри Telegram. Отдельного приложения с другой моделью прав нет: пароль/сессия/CSRF/роль и подтверждения операций остаются обязательными. Telegram initData не используется для входа, bot token в браузер не передаётся.

По умолчанию выключено. Сейчас origin — частный LAN HTTPS с локальным CA. Xray разрешает только исходящий Telegram HTTPS; он не является обратным туннелем к пульту. Условие активации: с этого телефона уже открывается адрес пульта, маршрут доступен и сертификат доверен, затем отдельно проверяется Telegram WebView. Некоторые WebView могут иметь отдельные правила доверия локальному CA. Без этих условий кнопка не создаст доступ из дома. Публикация админки, смена маршрутов/CA, TUN и firewall этим переключателем не выполняются.

После проверки доступа на телефоне включить:

```bash
sudo /opt/ustar-console/venv/bin/ustar-console-setup --telegram-mini-app on
```

Снова отправить `/start`, нажать «🖥 Пульт», проверить открытие, обычный вход и запрет недоступных роли операций. Пока это не проверено, Mini App не считается принятой. Отключение:

```bash
sudo /opt/ustar-console/venv/bin/ustar-console-setup --telegram-mini-app off
```

После отключения снова `/start`. Эти команды меняют только явный opt-in в приватном credential и перезапускают notifier; существующие token/proxy/IDs сохраняются. При возврате к старому выпуску, не знающему поля mini_app, это поле нужно удалить из приватного JSON локально до запуска старого notifier; `off` в текущем выпуске сохраняет Boolean false.

Обязательный следующий сетевой этап при необходимости доступа из дома — [изолированный userspace/SSH pilot](HOME_ACCESS_PLAN_20261018.md). Он остаётся отдельной работой, требующей проверки стабильности домашней LAN/Internet; VPN этим пакетом не устанавливается.
