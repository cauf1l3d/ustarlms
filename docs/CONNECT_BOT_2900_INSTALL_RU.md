## Что изменится

В Telegram появятся русские кнопки, пошаговые формы, короткие пояснения, статусы,
прогресс и компактные таблицы. Сотрудник сможет отправлять отчёты с фото и чек-листы;
руководитель — назначать задачи и проверять отчёты; HR/HRD — работать с доступными
аттестациями, заявками, повторными курсами и адаптацией; руководитель компании —
открывать сводку. Права определяются той же учёткой Академии.

Кадровые решения, ручные оценки, повторное обучение и решения по адаптации
подготавливаются в боте и подтверждаются своей учёткой на странице Академии
из офисной сети. Новый сотрудник подаёт анкету без пароля; первый пароль после
одобрения настраивается отдельно в Академии. Полные курсы, Quiz, SCORM и Студия
открываются в Академии. Mini App и публичный HTTPS — последующий этап.

Установщик сохраняет прежние привязки, link/ACK ключи, курсор, журнал доставки,
личные настройки и историю. Ключ рабочих операций отдельный. Получатели новых
уведомлений — активные связанные сотрудники с личным согласием; старые события
не рассылаются заново. Три новые таблицы содержат только диалоги и квитанции,
вторая кадровая или учебная база не создаётся.

## 2. Установка в отдельной службе

```bash
sudo systemd-run --unit=ustar-connect-role-bot-update-99dbecaa \
  --property=Type=oneshot --property=TimeoutStartSec=infinity \
  /usr/bin/python3 -I -B -u /root/ustar-connect-role-bot-install-99dbecaa/update.py \
  --upgrade --acknowledge-outage
sudo journalctl -fu ustar-connect-role-bot-update-99dbecaa.service -o cat
```

Дождаться завершения приложения и затем `runtime_active` с
`role_bot_enabled:true`, `local_ustar:2026102900`, а также успешного завершения
службы. `app_ready` — промежуточный этап, переключение worker идёт следом.
Ctrl+C закрывает просмотр журнала; отдельная служба продолжает работу.

## 4. Короткая приёмка в Telegram

Открыть `@ustarcorp_bot` и нажать «Запустить», затем пользоваться меню.
Уже связанная учётка получает текущие рабочие разделы. Для первой привязки:
«Личный кабинет → Мессенджеры» в Академии, персональная ссылка и подтверждение
с обеих сторон. Сервисный Moodle site administrator не является сотрудником;
для рабочих сценариев нужна обычная кадровая учётка с соответствующей ролью.
Для нового сотрудника после решения HRD администратор задаёт временный пароль
в native карточке пользователя с обязательной сменой и передаёт его лично.
Сотрудник входит в Академию, меняет пароль и нажимает в боте «Проверить доступ».

| Кто проверяет | Действие | Ожидаемый результат |
|---|---|---|
| Сотрудник | Мои задачи → отчёт с фотографией до512КБ → отправить | Один отчёт в Академии, статус «На проверке» |
| Руководитель | Вернуть с причиной → принять исправление | Комментарий, автор и история сохранены |
| Сотрудник | Чек-листы → заполнить → отправить | Один итог за текущий день |
| HR | Аттестации → оценка → подтвердить в Академии | Оценка записана в ту же попытку своим автором |
| HRD | Тестовая заявка → решение → подтвердить в Академии | Статус заявки изменился один раз |
| Руководитель компании | Сводка компании | Текущие показатели Академии, доступные по роли |
| Сотрудник | Настройки → выключить уведомления; затем отозвать связь | Личное выключение и отзыв соблюдаются |

Новое нажатие старой кнопки после изменения записи должно предложить открыть
карточку заново. При неопределённом результате сначала проверить состояние;
повторная отправка бизнес-действия автоматически не выполняется. Пароли и коды
в Telegram вводить не нужно. Эта приёмка выполняется владельцем: агент не
отправлял реальные сообщения в Telegram и не устанавливал комплект на сервер.

## Восстановление и временное отключение

При незавершённой операции, после остановки установочной службы:

```bash
sudo /usr/bin/python3 -I -B -u \
  /root/ustar-connect-role-bot-install-99dbecaa/update.py --recover
```

До публикации приложения восстанавливается согласованная2803 копия; после
публикации завершается2900 с сохранением новых записей. Незавершённое переключение
бота возвращает прежний worker и профиль, сохраняя приложение2900.
Затем согласованный бот можно включить повторно:

```bash
sudo /usr/bin/python3 -I -B -u \
  /root/ustar-connect-role-bot-install-99dbecaa/update.py --enable-bot
```

Временно вернуть прежний профиль Connect без отката приложения:

```bash
sudo /usr/bin/python3 -I -B -u \
  /root/ustar-connect-role-bot-install-99dbecaa/update.py --disable-bot
```

Полный поздний `--restore` удаляет записи после снимка и требует отдельных
явных флагов; для обычного восстановления используется `--recover`.
Журнал `/var/lib/ustar-connect-role-bot-update` и общие locks не удалять.
При `managed_operation_busy_retry_later` дождаться завершения управляемой операции.

## Пассивный сборщик: 30 октября, 11:00 МСК

он не создаёт искусственную нагрузку и не включает расширения PostgreSQL.

```bash
sudo systemd-run --unit=ustar-workday-20261030-01 \
  --property=Type=oneshot --property=TimeoutStartSec=9h \
  --property=MemoryMax=384M --property=CPUQuota=10% --property=Nice=10 \
  /usr/bin/python3 -I -B -u /root/ustar-connect-role-bot-install-99dbecaa/observe.py \
  --collect --duration-seconds 28800 --interval-seconds 60 \
  --output-dir /var/lib/ustar-workday-20261030-01
```

После завершения прислать `summary.json` или архив отчёта. Apache агрегаты
не подменяют отдельные измерения SQL/page, браузерного LCP и SLO.
