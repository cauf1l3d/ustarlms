# Одноразовая HR-миграция 2724

Файлы здесь — точные исторические копии одноразовых операций и диагностических фикстур. По прежним путям в `moodle/local/ustar/cli/` находятся блокирующие заглушки с кодом завершения 78. Они не предназначены для повторного исполнения; архив нужен для инженерного аудита.

| Команда | Причина блокировки |
|---|---|
| `hr_canonical_2724_apply.php` | Очистка с жёсткими production ID, удаляющая историю и меняющая аккаунты. |
| `probe_development_assessment.php` | Диагностика пишет попытки в базу и без `--userid` выбирает первого сотрудника. |
| `ensure_demo_executive.php` | Выдаёт повышенную роль жёстко заданному логину. |
| `normalize_demo_positions.php` | Меняет действующую структуру под демонстрационные должности. |
| `ensure_tasks_2725.php` | Одноразовая перенастройка расписания задач для старой версии. |
| `assessment_lifecycle_probe.php` | Диагностика синхронизирует и записывает lifecycle при просмотре сотрудника. |
| `reconcile_assessment_runtime.php` | Массовый repair меняет runtime и создаёт события оценки без предварительного плана и ссылки на backup. Для новой операции нужен scoped manifest и явное подтверждение. |
| `import_structure.php` | Переписывает JSON структуры напрямую, обходя новый канонический редактор и проверку влияния на сотрудников. |

Остальные команды CLI требуют отдельной классификации по A05: наличие `probe`, `check` или `validate` в имени само по себе не гарантирует отсутствие записи в базу. Не считайте это архивирование завершением A05.
