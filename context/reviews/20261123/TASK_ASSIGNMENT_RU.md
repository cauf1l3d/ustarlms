# Постановка задач сотруднику, отделу и должности

23.11.2026 МСК · `2026112302` · `1.22.0-rc.4`. Владелец подтвердил обновление server1 до `2026112301`. [Квитанция](../../runtime/workplace_home_owner_deploy_20261123.json)

## Правила назначения

| Получатель | Кто получает | Что видит постановщик |
|---|---|---|
| Сотрудник | Один выбранный действующий сотрудник из текущей области назначения | Имя получателя. Поиск по имени дополняют необязательные фильтры отдела и должности |
| Отдел | Один действующий руководитель отдела или официально назначенный и. о. | Имя руководителя. При вакансии, неоднозначности или отсутствии права форма объясняет, почему назначение недоступно |
| Должность | Каждый действующий сотрудник с этой основной должностью в текущей области назначения | Список, число получателей и подтверждение с итоговым числом. Каждый ведёт свой отчёт, статус и обсуждение |

Руководитель назначает задачи в управленческом контуре действующей оргструктуры. Пользователь с действующим полномочием назначения по всей компании видит общую область. Исключены сам постановщик, неактивные и служебные учётные записи и сотрудники с конфликтом оргпривязки. Роль и права получателей повторно проверяются при отправке. Для должностей берётся текущая основная оргпривязка по принятому правилу. Временное исполнение руководящей роли учитывается при назначении отделу. [Правила оргидентичности](../../decisions/ADR-0008-feed-audience-and-authorship.md)

Групповой выбор поддерживает поручения, чек-листы и их индивидуальные серии. Состав фиксируется при создании. Дочернее поручение, связь с брифингом и повторный курс привязаны к одному сотруднику. За одну отправку можно назначить до 100 задач.

## Инженерное ревью

| Наблюдение | Изменение |
|---|---|
| Фильтр требовал пройти три поля и сделать отдельный переход перед заполнением задачи | Форма расположена перед списком. Переключение получателя и фильтры работают на странице и сохраняют введённый текст. Без JavaScript действует серверное подтверждение выбора |
| Нет заранее видимого адресата или состава должности | Получатель, число и список формируются из того же правила, которое проверяется в момент записи. Изменение состава возвращает черновик и актуальный предпросмотр |
| Для каждого кандидата заново обходилось дерево руководителя | Общая область строится один раз на операцию выбора. Имена читаются одним запросом. Право на запись проверяется отдельно. Разрешение основной оргпривязки всё ещё выполняется для каждого кандидата |
| Материалы повторного курса подгружались при создании обычной задачи | При динамическом выборе список запрашивается после выбора повторного обучения. В режиме без JavaScript список доступен после серверного выбора сотрудника |
| Групповая запись могла бы создать часть задач или продублировать их при повторном POST | Весь набор пишется через транзакцию Moodle. Повтор того же запроса возвращает сохранённый результат. Изменённые данные с уже использованным ключом отвергаются |
| При прикреплении файлов группа перечитывала бы каждое вложение по числу исполнителей | Загрузка обрабатывается один раз. Moodle File API создаёт отдельные файловые записи на задачи с общим содержимым и индивидуальным контролем доступа |

## Измерение

При повторном построении списка для руководителя с 20 подчинёнными на Moodle 5.1.8 и PostgreSQL 17.11 число чтений БД снизилось с **12 478 до 742**. В обеих версиях сверены те же 20 получателей. Замер охватывает получение списка, без загрузки страницы, записи задач и отправки уведомлений.

## Проверки

В нативные проверки включены область директора и руководителя, действующий и. о., конфликт двух и. о., реальный состав должности, смена состава и повторная отправка. Браузерный сценарий проходит смену адресата без потери черновика, назначает трём получателям один текст и проверяет, что каждый из трёх может открыть вложение через собственную задачу. Серверная форма также проверена с клавиатуры на ширине 390 px при отключённом JavaScript. Проверка работающих ролей и задержек на server1 выполняется после установки.
