# R16: context boundary and read-only R00 audit

Status: implementation locally verified; deployment not performed. Do not mark R16 released/done until the server installer and tests pass. The daemon remains stopped. R00 still requires the actual production manifest and review of differences.

## Scope

Only harness, generator scripts, tests and this documentation change. No Moodle application files, schema, startup units, network listeners or generated context snapshots are included. Existing uncommitted context is not committed or overwritten.

`safe_context.py` allows UTF-8 `.md`, `.txt`, `.json`, `.yaml`, `.yml` within `context/`, with a 512 KiB per-file limit, 2 MiB collection budget and 256-file enumeration limit. Oversized collections are bounded subsets, not complete dumps. It rejects absolute paths, traversal, hidden paths, unsupported formats, non-regular files, invalid UTF-8/NUL, hardlinks and all symlinks. Linux directory descriptors and O_NOFOLLOW protect component-by-component access and pathname replacement races. All tool readers use this boundary. Files deliberately placed in context must still be suitable for disclosure; this is not content redaction or a sandbox against an administrator who controls the repository.

Transport is explicit local stdio; no HTTP/SSE listener or authentication endpoint is introduced. Access follows the local MCP client's process/OS permissions. Run only as an unprivileged user with read access to approved context, never as root. A systemd daemon is not required for stdio. The protocol fixture process runs only during tests and exits afterwards.

SDK dependencies are pinned to tested MCP 1.30.0 and PyYAML 6.0.3. The v1 FastMCP API is intentional; the old unbounded `mcp` dependency could silently change API major versions. Reference: https://github.com/modelcontextprotocol/python-sdk (v1 compatibility guidance).

## Generator and R00

`refresh_context.sh --output-dir /absolute/new/directory` saves staged/unstaged diff, status and untracked path list (not untracked file contents), then collects selected Docker state, health, started_at/uptime, actual PHP and database/disk versions. Git source and production runtime are separate records. The Moodle config candidate is found under Docker mount destinations; actual CFG dirroot is mapped through the longest matching bind mount. Unsupported/missing mounts and failed probes produce explicit errors, never fabricated version numbers.

The version probe uses Moodle CLI bootstrap with cookies/caches disabled; subsequent version queries use PostgreSQL read-only mode. It does not call business sync/completion/migration APIs. Bootstrap is still Moodle PHP, so this is not a filesystem sandbox against custom bootstrap code. No Docker Env, passwords or full diagnostic stderr are saved. PostgreSQL version comes from the connected Moodle database, not a hardcoded value or only a binary version.

The snapshot includes an index that excludes itself, symlinks, hidden/non-text and oversized files. The new source code map inventories files at the exact Git SHA. Existing repository context/index and generated code maps are preserved until explicit review/promotion. `runtime.json`, `context/runtime/*.yaml` (JSON-compatible YAML), `production_manifest.json`, `comparison.md` and SHA256SUMS are written outside the repository.

Production inventory covers local/ustar and theme/ustar and compares SHA-256 with `23243f3de9b0392aded2635f84291dd8702e4920`. Reports separate changed, matching, production-only, Git-only and uncompared entries. Symlinks, hidden files and config.php/config-local.php are excluded/reported. Read failures and exclusions make completeness false. The inventory is not an atomic filesystem snapshot; changed-during-read files are rejected. Hash comparison does not compare database schema, establish deployment equivalence or authorize copying files.

Exit 0 means collection completed, not that hashes match. Exit 2 means incomplete evidence; inspect errors and exclusions. No automatic copy/repair, cache purge, service start, commit or push is performed by collectors.

## Validation

Linux / Python 3.12; MCP 1.30.0 / PyYAML 6.0.3. Run:

```sh
python3 -m venv harness/ustar-contextd/.venv
harness/ustar-contextd/.venv/bin/pip install -r harness/ustar-contextd/requirements.txt
harness/ustar-contextd/.venv/bin/python -m unittest discover -s tests/r16 -v
```

Tests cover traversal variants, symlink/root/directory/leaf replacement, hardlink, FIFO, missing/directory/oversized/non-text input, aggregate limits, all common readers, real stdio requests on synthetic files, index repeatability/self-exclusion, mount selection, health/uptime, version command, manifest classification and preservation of dirty context. No production secrets were used. A real Docker/Moodle/PostgreSQL probe cannot be executed from the isolated workspace because 192.168.1.60 is unreachable. User-supplied server observations remain separate evidence, not locally measured facts.
