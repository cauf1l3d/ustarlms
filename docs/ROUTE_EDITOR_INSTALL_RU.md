## Что изменилось и как пользоваться

- На карточке — «Скрыть шаг / Вернуть шаг». Это отдельная команда, которая не пересобирает обучение и не создаёт новую версию. Перед скрытием раскрываются область изменения и подтверждение. Общий шаг скрывается в общем маршруте. Для override остаётся «Вернуть общий вариант» по ADR0004: должность снова получает общий шаг.
- В редакторе показан полный список «Что нужно пройти». Обязательность, ознакомление и главный навык задаются на своей строке. Существующие источники сохраняются; для удаления нужно явно отметить «Убрать из новой версии». Найдите новое обучение, выберите его в новой строке, при необходимости нажмите «Добавить ещё строку». Поиск и добавление работают без JS; в списке до200совпадений, выбранное значение сохраняется.
- «Сохранить черновик» сохраняет авторскую версию; сотрудник продолжает видеть прежнюю публикацию. «Опубликовать изменения» проверяет совместимость и готовность обучения. Неполный черновик не публикуется автоматически. Чтобы убрать весь шаг у сотрудников, используйте скрытие на карточке.
- Дополнительные SCORM/повторные настройки сворачиваются, их значения сохраняются. Допустим минутный срок. Скрытые точки остаются в авторском списке с отметкой. При перемещении стрелками скрытые карточки пропускаются. Загрузка файла/видео из шага сохранена.
- Ошибка показывается рядом с формой с сохранением ввода. При конфликте версии скопируйте свой текст, затем обновите страницу для сверки; повтор старой формы не перезапишет новые данные.

История версий, попытки, прогресс и награды не удаляются. Установка не меняет бизнес-данные.
Полная оптимизация route readers остаётся в общем плане; production SLO этим пакетом не измерен. Точный случай owner invalidparameter требует повторить действие на проблемной точке после установки.

Ожидается `Result=success`, `ExecMainStatus=0`, конечный `phase=active`.
`inactive/dead` для завершённого oneshot нормально. Применение кратко перезапускает веб-контейнер и очищает кэши; `database_changed=true` относится к кэшу, `business_data_changed/schema_changed/worker_changed=false`. Readonly check — без изменений.
Если busy — дождаться текущей операции, не удалять lock-файлы. При другом отказе сохранить journal/check; старый discovery-архив не накатывать поверх. Recovery восстанавливает source/metadata этого пакета и не является обязательным вторым шагом.

## Приёмка владельцем

Открыть проблемную точку → проверить все строки → сохранить черновик → убедиться, что у сотрудника осталась прежняя публикация → скрыть отдельной кнопкой → проверить отсутствие у сотрудника → вернуть → проверить прежнюю публикацию. Затем опубликовать осмысленные изменения. Для общего шага проверять влияние на семью, для override — возврат общего варианта. При повторной ошибке сохранить текст и контекст формы для дальнейшего разбора.
