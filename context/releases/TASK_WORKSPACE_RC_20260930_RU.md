# USTAR 1.10.0-rc.1: задачи и контроль

Кодовый PR: https://github.com/cauf1l3d/ustarlms/pull/64. База — PR #63, SHA `9b1810d73951756b5b2d747a3aecaae371298bc4`, версия плагина `2026092907`. Кандидат — `2026093001`. Точный итоговый SHA и результаты gate фиксируются в PR; архив необходимо брать из успешно завершённого **full-rc запуска именно этого SHA**.

## Поведение

- Штатная вкладка задач: обзор, календарь, чек-листы, контроль, аналитика, правила. Поиск исполнителей ограничен текущей областью управления. Доступны связанные поручения в пределах срока родителя.
- Редактор рабочих шаблонов: отметка, текст, число, фото; обязательность, порядок, вес KPI. Публикация создаёт новую версию. Старые назначения и серии не меняются.
- Отчёт: черновик, отправка, принятие или возврат с комментарием. История версий сохраняется. До отправки текст и фото черновика доступны исполнителю. Фото: до пяти настоящих JPG/PNG/WebP, до 8 МБ каждое с учётом лимита сайта. Вложения хранятся в Moodle File API, прямой URL повторно проверяет доступ.
- Серии: выбранные дни, исключённые даты, часовой пояс, конечная дата до года. Cron создаёт отдельные выполнения на две недели вперёд. При утрате автором текущих полномочий серия останавливается. Пауза не создаёт задания за пропущенные дни при возобновлении.
- Проверяющий определяется по действующей оргструктуре. Срок проверки отдельный от исполнения. Уведомление перед сроком, затем настроенная цепочка эскалации: прямой/следующий руководитель, HRD. Напоминание считает обычные минуты; сроки проверки и эскалации — выбранный рабочий либо календарный режим.
- Повторное обучение можно назначить только по подтверждённой ранее теме из существующего маршрута. Завершение требует нового канонического учебного результата; ручная отправка такого поручения запрещена.
- KPI: принятые баллы / баллы заданий с наступившим сроком. Аналитика не включает личные заметки, отменённые и будущие задачи. «Вовремя принято» означает, что принятый отчёт был отправлен не позже срока, а не скорость решения руководителя.

## Изменения базы и прав

Добавляются `local_ustar_task_meta`, `task_templates`, `task_tpl_versions`, `task_series`, `task_reports`, `task_escalations`, `task_settings` (все с префиксом `local_ustar_`). Существующие задачи, личные заметки, учебная и кадровая история не переписываются.

Capability `local/ustar:taskescalation` явно добавляется штатным ролям `ustar_hrd` и `ustar_superadmin`. Назначения людей на роли не меняются. Новый scheduled task `local_ustar\task\process_work_tasks` запускается раз в пять минут; уведомления используют существующую очередь доставки. Отдельный постоянно работающий сервис не требуется.

## Проверки кандидата

Обязательный `USTAR review gate`: source/PHP lint, frontend, rollback drill, frozen package, Moodle install → upgrade → повторный upgrade → свежая установка → schema parity → полный PHPUnit. Дополнительно DOM-тест редактора проверяет типы/скрытые поля, стабильные ключи, перестановку и ограничения.

Сам gate не проверяет внешний вид новой штатной Moodle-страницы в авторизованном браузере, реальную оргструктуру вашего сервера и delivery внешнего транспорта. Эти пункты принимаются на тестовой копии сервера до промышленного переключения. Не считать HTTP 303 неавторизованной страницы проверкой её бизнес-сценариев.

## Внедрение

1. Зафиксировать итоговый SHA из PR и скачать `frozen-release-candidate` из соответствующего зелёного full-rc запуска. Сверить manifest и SHA архива. Не использовать `main`, текущую ветку или старый артефакт другого запуска вместо замороженного кандидата.
2. На сервере выполнить `bash scripts/release/task_workspace_preflight.sh`. Скрипт ничего не меняет. Ожидается установленная версия `2026092907`, исходная схема PR #63 и выключенный maintenance. Если версия/источник другой — сопоставить drift до обновления.
3. Сделать согласованный снимок БД, moodledata, config.php и текущего кода/образа. Проверить, что снимок можно восстановить. Путь хранения и способ восстановления зависят от вашего Docker compose/томов; этот RC их не угадывает.
4. Сначала установить кандидат на восстановленную тестовую копию. Перенести содержимое `moodle/local/ustar` и при необходимости сопровождающий theme из замороженного пакета в реальные bind mounts/образ, сохранив config.php и moodledata. Не копировать весь архив поверх Moodle core.
5. В тестовой копии включить maintenance, запустить штатный `admin/cli/upgrade.php --non-interactive`, затем `purge_caches.php`. Проверить `local_ustar=2026093001`, все семь таблиц и регистрацию scheduled task. Повторный upgrade должен быть безопасен.
6. Выключить maintenance и пройти сценарии ниже. Только после принятия повторить те же действия в согласованное окно на платформе, предварительно сделав новый полный снимок. Для контейнера `ustar_moodle` штатные команды выполняются как `sudo docker exec -u www-data ustar_moodle php /var/www/html/admin/cli/...`.

## Приёмка на тестовой копии

| Роль / сценарий | Ожидаемый результат |
|---|---|
| Руководитель создаёт обычное поручение | Исполнитель находится только в его области; задача видна в списке и в календаре на срок |
| Исполнитель сохраняет отчёт, потом отправляет | Черновик не завершает задачу; отправка создаёт отдельную версию и очередь проверки |
| Руководитель принимает / возвращает | Принятие даёт KPI; возврат требует комментарий, не удаляет старый отчёт |
| Чек-лист с обязательным фото | Без настоящего фото отправка запрещена; снимок можно открыть только с правом на эту задачу |
| Редактор меняет шаблон | Существующее выполнение сохраняет старые поля и вес; новое использует новую версию |
| Повторение и повторный cron | Создаются отдельные датированные задания без дублей; исключённые даты пропускаются |
| Смена руководителя | Старый руководитель теряет доступ; новый получает проверку по текущей цепочке |
| Просрочка исполнения / проверки | Отдельные цепочки и журналы; повторный cron не дублирует доставку |
| Вложенное поручение | Родитель нельзя отправить, пока активен ребёнок; срок ребёнка ограничен родителем |
| Повторное обучение | Старое прохождение сохраняется; задача закрывается только новым материалом и аттестацией |
| Личный блокнот | Не доступен HR/руководителю, не входит в статистику; старые заметки сохраняются |
| Телефон и desktop | Кнопки/формы читаемы; календарь можно прокручивать; клавиатура и фокус работают |

## Откат

После миграции нельзя понижать `local_ustar` простым возвратом старого каталога: Moodle не поддерживает downgrade схемы. В случае отказа вернуть согласованный снимок **БД + moodledata + код/config/образ**. Данные и отчёты, появившиеся после снимка, нужно сохранить отдельно по принятому плану; не удалять новые таблицы вручную. Тренировка отката gate проводится на синтетической изолированной среде и не подтверждает восстановимость ваших production-томов.

Статус: кандидат на проверку; production deployment и приёмка ещё не выполнены. PR #64 зависит от PR #63 и не должен внедряться как небольшой diff поверх исторического main.
