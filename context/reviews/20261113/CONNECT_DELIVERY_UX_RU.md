## Инцидент и исправления

| Приоритет | Доказательство | Исправление |
| --- | --- | --- |
| P1 | Запись №508 в 06:17:07 дала `unavailable`; в БД одна попытка, затем `uncertain`. В старом worker результат `unavailable` после выданного разрешения достигается до вызова Telegram. Moodle задаёт `send_before = server_now + 10`, старый Python сравнивает его с `requested + 10`. Тест воспроизводит отказ на переходе одной секунды. Содержимое исторического ответа разрешения в журнале отсутствует. | Проверка срока учитывает время получения и ограничивает полный интервал запроса. Отказы до вызова Telegram получают ограниченные повторы и точную причину. После возможного вызова Telegram неопределённый результат остаётся терминальным для автоматики. |
| P1 | Ошибка чтения файла до `begin` оставляла `leased`, после истечения срока worker повторно брал его без увеличения попыток. | Состояние и причина сохраняются в существующей очереди. Повтор ограничен пятью попытками. Разрешение на отправку повторно сверяет контент и получателя. |
| P1 | `nextattempt` исключал запись из выдачи после изменения тихого часа. Прочтение локального уведомления могло отменить явно подтверждённую рассылку. | Сохранение личных настроек будит только записи, отложенные личным расписанием. Прямые рассылки сохраняют явное поручение при прочтении локального уведомления. Ограничения Telegram и привязка продолжают действовать. |
| P1 | В Ленте удаление находилось внутри формы редактирования отдельной публикации. Модератор без права редактирования не видел действие. | У автора отдельная кнопка на карточке. У модератора отдельно «Скрыть публикацию» с причиной. Публикация и её не начатые отправки меняют состояние одной транзакцией. |
| P2 | `pending` и `leased` на экране назывались одинаково, причина задержки и срок отсутствовали. Счётчик «0» не отличал новые адресаты от уже поставленных. | Сводка и поимённая история, причина, ближайшая проверка и ручное обновление. Формулировка количества описывает тех, кого ещё можно добавить. |

Нормальная цепочка — зафиксировать поручение вместе с очередью, забрать запись по аренде, проверить права и файлы, получить короткое разрешение, выполнить один вызов отправки и записать квитанцию. Отдельный ответ «Принял» фиксирует подтверждение сотрудника. Изменение публикации или потеря доступа проверяются на каждом этапе до отправки. Подтверждение Telegram фиксирует приём сообщения сервисом.

Перед расширением измерить запросы и задержку предпросмотра на тестовых 10/100/500 получателях. Если измерения подтвердят узкое место, пакетно подготовить неизменяемые для запроса данные и сохранить повторную персональную проверку перед доставкой.

## HTML-виджет для короткого чек-листа

Bot API 10.4 поддерживает `sendWidget` для личных чатов. Telegram отображает HTML/CSS/JS внутри сообщения. Скрипт работает в QuickJS без сети. Доступны кнопки; поля ввода и загрузка файлов требуют обычного диалога. HTML ограничен 32 768 байтами и 4 096 байтами после zlib, состояние `chat_data` — 1 024 байтами, команда `TelegramWidget.request()` — 64 байтами. [Спецификация Telegram](https://core.telegram.org/bots/widgets#limits-and-quotas).

| Этап | Что проверить |
| --- | --- |
| Короткий личный чек-лист | Одна карточка на сегодня. Пункты, явные ответы, счётчик и «Отправить». До подтверждения можно исправить ответ. После — показать результат и время. |
| Одна задача | Название, срок, статус и одно уместное действие. Для комментария, фото или сложного отчёта переход в существующий диалог. |
| Контракт | Получать `widget_query` в действующем receiver, принимать только обычную команду данных. Сверять личный чат, привязку, конкретное сообщение, полномочия, срок, версию и повторы. Подтверждение вызывает действующие сервисы задач и чек-листов. |
| Права и данные | Использовать персональные виджеты и минимальные данные. В `public_data` нет личных сведений. `chat_data` служит представлением серверного состояния. Авторизация и версии остаются в Академии. |
| Совместимость | Под карточкой оставить понятную кнопку обычного сценария и текстовое описание. Проверить iOS, Android, Desktop, старый клиент, потерю сети, повторное нажатие и изменение чек-листа в вебе. |

Встроенный виджет может обращаться к уже работающему боту через Telegram. Для такого пилота хватает текущего закрытого моста; отдельный публичный сайт нужен другому формату, Mini App. Продуктовое включение виджета требует теста актуальных клиентов и согласования объёма сведений, передаваемых в Telegram. Пилот виджетов вне пакета исправления доставки.
