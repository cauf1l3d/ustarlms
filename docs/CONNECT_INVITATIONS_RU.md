# Первое подключение сотрудников к боту Telegram

14 ноября 2026 г.

## Настройка Академии

В пилоте используется существующая локальная учётная запись действующего сотрудника.
Академия показывает в личном чате действующие документы обработчика Moodle «Политики»
для зарегистрированных пользователей. Для работы в чате опубликуйте текстовую редакцию
документов. Принятие действующей редакции в Академии действует и в боте. Если меняется
редакция, бот запросит согласие с новой версией.

Включение выдачи приглашений управляется флагом
`$CFG->ustar_connect_bot_invitations_enabled = true;` в существующем конфигурационном файле
Moodle рядом с настройками Connect. Проверка состояния и отзыв активных связей доступны
администраторам из раздела «Мессенджеры → Приглашения Telegram».

## Выдача приглашения

1. Откройте «Мессенджеры → Приглашения Telegram» в Академии и найдите сотрудника по имени или логину.
2. Если у вас есть подтверждённый числовой Telegram ID сотрудника, укажите его. В противном случае оставьте поле пустым.
3. Передайте ссылку или код сотруднику по его рабочему контакту. Приглашение действует 10 минут.
4. Сотрудник открывает ссылку и нажимает Start или вставляет код в личный чат с ботом.
5. Если Telegram ID не был указан, сотрудник передаёт показанный ботом код подтверждения через известный рабочий контакт. Администратор вводит его в открытом приглашении. Затем сотрудник нажимает «Проверить подключение».
6. Если нужны согласия, сотрудник читает документы и нажимает «Принять соглашение». После последнего необходимого согласия открывается рабочее меню. Принявший действующую редакцию сотрудник сразу видит меню.

Для доступа по приглашению сотрудник может работать с личными задачами, чек-листами,
обучением и настройками. Смена первого пароля остаётся частью браузерного входа в Академию.
Роли с административными полномочиями, внешняя аутентификация и дополнительный фактор
требуют стандартного входа. Ссылку можно отменить до привязки. После привязки доступ
отзывается в списке связей, а следующее подключение требует нового приглашения.

## Проверка на сервере перед пилотом

Команда выводит тип обработчика и число опубликованных редакций. Она не выводит текст
документов или данные сотрудников.

```bash
sudo docker exec -i -u www-data ustar_moodle php <<'PHP'
<?php
define('CLI_SCRIPT', true);
require '/var/www/html/config.php';
$tx = $DB->start_delegated_transaction();
$DB->execute('SET TRANSACTION READ ONLY');
$manager = new \core_privacy\local\sitepolicy\manager();
$handler = ltrim($manager->get_handler_classname(), '\\');
$policies = $handler === \tool_policy\privacy\local\sitepolicy\handler::class
    ? count(\tool_policy\api::get_current_versions_ids(\tool_policy\policy_version::AUDIENCE_LOGGEDIN))
    : 0;
$tx->allow_commit();
echo json_encode(['handler' => $handler, 'published_employee_policies' => $policies]), PHP_EOL;
PHP
```

Для проверки пилота используйте обычного сотрудника с локальной учётной записью,
подтверждённым Telegram ID и установленным требованием сменить первый пароль.
Проверьте показ текста, запись версии в админке «Политики», открытие меню, повторный
вход и отзыв связи. Один сотрудник с уже принятым соглашением позволяет отдельно
проверить, что бот сразу показывает меню.
