# Приглашения в рабочий бот и соглашения Академии

Пилот для действующих сотрудников с существующей записью Moodle. Администратор Академии
выдаёт приглашение в приватном HTTPS-сеансе и передаёт его лично. Сотрудник нажимает
«Старт» по ссылке или вставляет одноразовый код после «Подключить рабочую учётку».
Проверенный Telegram ID позволяет привязать аккаунт сразу. В остальных случаях
сотрудник сообщает код заявки по известному рабочему контакту, администратор сверяет
и подтверждает его. Рабочее меню открывается после принятия документов.

1. Сохранить приглашение в реестре Connect с отдельной областью токена, сроком 10 минут
   и автором. Использовать общий lock, транзакцию и существующую уникальность связей.
   Разрешить администратору отменить приглашение и отозвать созданную связь.
2. Передать ссылку и ручной ввод через существующий подписанный bot.update. Ограничить
   попытки, сохранить только хеш, открыть работу только для текущего Telegram ID.
3. Разрешить пропустить требование первого пароля только на приглашённой связи в боте.
   Сохранить MFA, внешний вход и правила браузерной авторизации. Для приглашённой связи
   использовать команды сотрудника и проверять полномочия при каждом запросе.
4. Читать действующие версии через tool_policy. Показывать полный доступный текст по
   страницам, сохранять явное решение через API Moodle от имени текущего сотрудника.
   Устаревшая кнопка не принимает новую редакцию. Необязательные документы можно отклонить.
   Сначала проверить реальный обработчик и наличие документов на сервере.
5. Проверить неверный ID, истечение, повтор/гонку, новую версию соглашения, отозванную связь,
   прежний вход с первым паролем, согласие в обоих направлениях и отказ при старой кнопке.
