# Connect: графические карточки и цветные кнопки

30.10.2026, Europe/Moscow. Основание — владелец подтвердил кнопки, передачу задач
между двумя учётками и синхронизацию с Академией; попросил цветные читаемые кнопки
и вывод картинками, как в USTAR-пульте. Продолжение действующего поручения29Oct:
самостоятельная реализация, без субагентов и новых согласовательных пауз.

## Решение и границы

Worker-only presentation update поверх app2900/worker5cc02944. Тот же Academy view,
те же callback tokens, права, writers и журнал событий; без SQL/миграции/нового ключа.
Точный оттенок и цвет текста кнопок принадлежат Telegram-клиенту. Используем
официальные primary/success/danger, нейтральную навигацию и короткие подписи.
На списках задач/заявок длинные подписи превращаются в номерные действия, а полное
переданное Академией название остаётся на карточке с тем же номером. Ограничения
исходного API (например52символа названия задачи) не выдаём за исправленные.

PNG: тёмный фон, жёлтый USTAR-акцент, крупные значения, progress bars и строки
без моноширинных таблиц. Снимок запроса с временем МСК; это не live dashboard.
Формы и длинные ответы сохраняют полный доступный текст: при нехватке места
используется прежний текстовый вариант без сокращённых номерных кнопок.

## Варианты

1. Pillow в worker: повторяет стек пульта, но добавляет native runtime dependency,
   venv и отдельное обновление среды. Для stdlib zipapp избыточно.
2. Рендер в Moodle: требует нового медиа-контракта и обновления приложения.
3. Выбрано агентом: небольшой предрасчитанный bitmap font из уже лицензированного
   Ustar Sans + stdlib PNG. Не меняет systemd/Python/бизнес-контракт.

Нет обращения к пульту, внешним render/font сервисам или генеративной графике.
Карточки создаются в памяти по уже разрешённому ответу. Секреты/callback/URL в PNG
не рисуются. Защита содержимого сохраняется.

## Доставка и обновление

sendPhoto/editMessageMedia с inline keyboard. Для заведомо отвергнутой картинки —
текст; при timeout/неоднозначном ответе автоматической повторной отправки нет.
Прежний journal не допускает повторного бизнес-действия. Фото отчётов — прежний путь.
Отдельный owner-executed guarded package: только worker pointer, те же службы,
профили, token и SQLite. Durable recovery возвращает прежний pointer и состояния
служб; журнал app2900 не переписывается. Старый installer2900 после нового worker
не использовать без возврата — новый check/recover входят в поставку.

## Приёмка

Реальный PNG/кириллица/переносы/границы, Telegram styles и числовое соответствие;
транспорт multipart, text-to-photo и photo-to-text; uncertain/replay; worker package
из immutable commit и возврат после прерывания. Production visual acceptance —
после установки владельцем. HRD и report-review сценарии по-прежнему не приняты.
