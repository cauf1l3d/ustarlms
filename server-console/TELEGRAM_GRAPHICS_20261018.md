# Графические карточки и реальные данные пульта — 18 октября 2026

Продолжение последнего запроса владельца из [общего диалога](https://chatgpt.com/share/6ad4957d-45f4-83eb-8db0-32e41a9137fd), 12:40 МСК: карточки подходят, если показывают реальные данные и читаются; в пульте нужно заполнить блоки доступными показателями. Настройка Telegram уже принята владельцем. Подключать нового бота, повторять setup или менять сеть для этого выпуска не требуется.

## Что показывает выпуск

| --- | --- |

Фигуры показываются только при свежем снимке и пригодной проверке соответствующего источника. Пропадание соединения скрывает текущие числа; история остаётся явно датированной. Отдельный статус notifier имеет срок45с даже при свежем host snapshot. При неполном SMART не выдумываются отсутствующие атрибуты.

## Доставка и ограничения

Изображение создаётся локально из фиксированных агрегатов. Raw SQL, логи, настройки, архивы, токены и ключи в PNG не помещаются. Нужны тот же разрешённый private user/chat и прежние проверки forwarded/bot сообщений. Лимит4 команды за10с и транзакция offset/outbox сохраняются.

Один логический ответ хранит PNG и полный текст. После принятого фото сохраняется отдельный прогресс: при перезапуске между фото и текстом повторяется только ещё не подтверждённый шаг. При неоднозначном обрыве сети возможен повтор сообщения, как и ранее (at-least-once). Определённый отказ Bot API принять фото или отсутствие renderer позволяет получить полный текст. Ошибки связи и429 сохраняют запрос для повторной доставки.

PNG ограничен256КиБ, общая очередь изображений —16МиБ; при заполнении бюджета новые ответы остаются текстовыми. Доставленные PNG удаляются из очереди. История инцидентов в БД ограничена1000 записями, API выдаёт100 последних. Нет отдельного накопления файлов-картинок.

Pillow13.0.0 зафиксирован с хешами. Кириллица берётся из включённых в wheel шрифтов Ustar Sans (подмножество DejaVu Sans, исходная лицензия рядом); системный шрифт или скачивание шрифтов во время работы не нужны. Независимый observer.pyz продолжает работать с текстовыми алертами без Pillow.

Передача фото использует прежний фиксированный `api.telegram.org:443`, проверку CA/hostname и при настроенном egress — только `127.0.0.1:18081` CONNECT. Произвольные URL/file_id/пути к изображениям не поддерживаются. Служебные unit-файлы и их права не меняются.

## Обновление и нативная проверка

Проверенный пакет и команды с точными source/hash будут записаны после завершения CI в receipt этого выпуска: [console_telegram_graphics_20261018.json](../context/runtime/console_telegram_graphics_20261018.json). Установка на server1 выполняется владельцем; у агента нет прямого SSH.

Updater сохраняет предыдущую venv целиком, отказывает при выполняющейся операции, устанавливает hash-locked зависимости и новый wheel, проверяет `pip check`, TLS и существующий ограниченный native acceptance. При ошибке возвращает прежнюю venv, включая прежнее отсутствие Pillow. Пароли, CA, bot credentials и очередь не пересоздаются.

После обновления:

1. Отправить боту по одной кнопке «Сводка», «Ресурсы», «Академия», «Бэкапы», «Стенды», «Алерты». Должны прийти PNG и подробный текст. Проверить читаемость на своём устройстве и фактическое время ответа.
2. Сверить показатели HDD с `df`/inode и время снимка. В пульте открыть «События»: живые правила и отдельно датированную историю. До первого нового перехода история может быть пустой; старые инциденты задним числом не восстанавливаются из текстов очереди.
3. Проверить, что существующий вход, роли и защищённое скачивание работают. После скачивания сравнить SHA256; это отдельная приёмка от создания архива.

## Какие блоки остаются без подключённого источника

Независимый HTTP и потеря server1 требуют наблюдателя на другом узле. Restore/RTO требует фактического восстановления и измерения времени. p95/5xx и сырые санитизированные логи требуют соответствующей телеметрии. Эти результаты не выводятся из локального HEAD, работающего бота или успешного CI. Домашний маршрут, Mini App, flexible TTL и web administration этим выпуском не устанавливаются.
