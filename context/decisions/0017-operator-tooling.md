# ADR-0017: Operator tooling

Дата:26.10.2026. Статус: принято в рамках текущей сверки; описывает границы, а не новый deploy.

Для управляемого изменения сервера использовать owner-executed инструмент с
check/apply/recover/status, явной областью, журналом намерения и проверяемой квитанцией.
Single-file доставка допустима, если исходники/состав/SHA связаны с Git и проверены
до исполнения. Default offline plan не меняет хост. Секреты — через private input,
не аргументы процесса или чат. Архив перед выдачей проверяется вместе со скачанной
сохранённой копией.

Container ID и соседние SHA защищают конкретную транзакцию от дрейфа. Они не должны
быть неявным вечным контрактом всей инфраструктуры. Новый routine lifecycle требует
отдельного профиля и проверенного recovery. Одноразовые старые операторы сохраняются
как исторические артефакты; не объединять их запуск в универсальный shell/framework.

Основание: scripts/infra, dated runtime receipts; текущие DB/code/backup инструменты
приняты в своей области. Замена поставленных pin-ов сейчас не разрешена этой ADR.
