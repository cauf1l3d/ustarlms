## Следующая сверка ядра

[`core_preflight.py`](../../scripts/infra/core_preflight.py) использует Git tree exact weekly SHA и streaming Git blob hashes установленных файлов. Для upstream metadata `git fetch --depth=1 --filter=blob:none` достаточен: tool не скачивает blobs и не выполняет PHP, bootstrap, SQL, cron или repair. Проверяемый upstream tree содержит **24 679** файлов в объявленной области, unsupported reference paths = 0.

Область: reference-tracked файлы и лишние имена. Исключены оба config.php, скрытые пути, tests/node_modules, root vendor и 19 известных plugin roots. Код внешних дополнений/vendor и секретная конфигурация этим отчётом не аттестуются; их provenance/compatibility требуют отдельной проверки при подготовке upgrade. Ссылки на файлы/директории отвергаются, изменение файла во время чтения отмечается ошибкой. Снимок не атомарный.

Оператор создаёт private каталог вне Moodle, получает **immutable version** скрипта с проверкой SHA-256, готовит отдельный bare upstream metadata repo и запускает:

```bash
sudo python3 -I /home/aduk/<private-preflight-dir>/core_preflight.py \
  --reference-repo /home/aduk/<private-preflight-dir>/upstream.git \
  --reference-commit 1cd17816c56a7df7ee796892efccaf1ed5347340 \
  --moodle-root /opt/ustar/data/moodle/public \
  --output-dir /home/aduk/<private-preflight-dir>/report
```

Конкретные пути генерируются через mktemp; этот пример не запускать с буквальным placeholder. Report directory создаётся оператором с mode 0700 заранее, чтобы отчёт можно было забрать. JSON не перезаписывается; вывод — только counts и путь. Exit 0 = совпадение объявленной области, 3 = differences, 2 = incomplete/error. Ни один результат не запускает repair. Перед публикацией полного JSON проверить extra/error names; в Git достаточно обезличенной сводки.

## Пункт 7 и оставшиеся входные условия

На 05.10 опубликован кандидат **Moodle 5.1.7**, upstream commit `fc6ed2622475d3aefd7ac8cf62adbe7dc3eda4a2`. [Release notes](https://moodledev.io/general/releases/5.1/5.1.7) разрешают прямой upgrade с 5.1.5 или более ранних; промежуточный 5.1.6 не нужен. Выбор ещё не означает stage/deployment. [Официальный upgrade guide](https://docs.moodle.org/501/en/Upgrading) требует согласованной DB/code/moodledata copy и проверки дополнений. Не обещать устранение H5P network timeout этим patch.

Следом нужны контракт existing backup wrapper, свежий recovery point после записей cron и изолированный upgrade/repeat/restore с сохранением дополнений и истории. Установленный wrapper hash подтверждён, но его CLI/source здесь ещё не получены: **не придумывать flags create/restore/rebind**. Старый snapshot 04.10 и successful restore остаются историческим доказательством.

CI сейчас PHP 8.2/8.2.30 и PostgreSQL 16.10. Новый exact candidate должен пройти full gate на выбранной PHP 8.3/Trixie/PostgreSQL matrix; source/frontend одной документационной поставки этого не доказывают. OS часть — patch updates Ubuntu 24.04, required AppArmor fix и обработка pending reboot с сохранением shared services. Проверить реальные Snap consumers до архивации старого профиля; не purge snapd, не отключать весь AppArmor и не создавать пустой include вслепую. SSH/MFA/firewall redesign остаётся другим отложенным пунктом.

Пункт 6 выполняется после patch/OS: DNS/CA trust, действующий Apache, wwwroot/proxy/cookies и реальные рабочие ПК/телефоны. Фактическое deployment evidence пока отсутствует. Production core, пакеты, данные, AppArmor и HTTPS этой repository-поставкой не изменены.
