# HTTPS пульта и Mini App: проверка без изменения сети

18 октября2026. Скриншот владельца показывает обход предупреждения Chrome для
`https://192.168.1.60:8443`. Это не подтверждённое доверие сертификату. Проверенный
локальный TLS сервера и доверие браузера/Telegram проверяются отдельно.

## На сервере после обновления пульта

Из каталога распакованного проверенного выпуска выполнить:

```bash
sudo /opt/ustar-console/venv/bin/python tools/console_access.py --repair-public-ca
sudo install -o aduk -g "$(id -gn aduk)" -m 644 \
  /etc/ustar-console/ustar-console-ca.cer /home/aduk/ustar-console-ca.cer
```

Помощник проверяет chain/срок/IP SAN и фактический сертификат слушающего пульта.
`chain_and_IP_SAN=pass` и `live_certificate=matches_verified_leaf` подтверждают
только эту часть. Печатается SHA256 публичного CA. Восстанавливаются только
публичные `.crt/.cer`; существующие CA/private keys, пользователи и пароли не меняются.
При ошибке цепочки или несовпадении live leaf остановиться на диагностике,
не перевыпускать CA и не отключать проверку TLS.

Перенести через WinSCP только `/home/aduk/ustar-console-ca.cer`. Закрытый `ca.key`
не переносится. `.cer` в DER: SHA256 файла совпадает с `ca_sha256` из SSH-вывода.

## Windows: доверие только для своего пользователя

Сохранить файл в «Загрузки». В обычном PowerShell:

```powershell
$ustarCA = "$env:USERPROFILE\Downloads\ustar-console-ca.cer"
Get-FileHash -Algorithm SHA256 $ustarCA
```

Сравнить результат с `ca_sha256` в SSH. При совпадении:

```powershell
Import-Certificate -FilePath $ustarCA -CertStoreLocation Cert:\CurrentUser\Root
```

Полностью закрыть Chrome и открыть снова. Проверить **точный** адрес
`https://192.168.1.60:8443`, без обхода предупреждения. Импорт не меняет маршруты,
DNS, VPN или хранилище сертификатов всех пользователей компьютера.

## iPhone

Установить тот же публичный CA: открыть файл → Настройки → «Профиль загружен» →
установить. Затем **Настройки → Основные → Об этом устройстве → Доверие
сертификатам → USTAR Console LAN Root CA → полное доверие**.
Простая установка профиля не включает TLS-доверие автоматически:
https://support.apple.com/en-us/102390 .

Сначала проверить точный адрес в Safari на этом же телефоне, затем кнопку
«Пульт» в нативном Telegram. Обход предупреждения Safari/Chrome не является
приёмкой Mini App.

## Телефонный VPN: маршрут и сертификат — разные проверки

1. С включённым VPN открыть точный адрес в Safari. Если есть ошибка сертификата,
   сетевое соединение уже дошло до HTTPS; продолжить проверку доверия/имени/срока.
2. Таймаут/отсутствие соединения — отдельная проблема маршрута. Если телефон в
   офисном Wi-Fi, конкретному VPN-клиенту нужен прямой доступ к адресу
   `192.168.1.60/32`, сохраняя Telegram через VPN. Настройки зависят от приложения;
   без его названия и текущего маршрута готовый профиль не выдумывается.
3. Из домашней или мобильной сети прямой адрес192.168.1.60 не достигнет офисного
   сервера только благодаря обычному VPN-провайдеру. Нужен собственный приватный
   маршрут или контролируемый reverse relay. Текущий Telegram-only Xray работает
   в исходящем направлении и такого доступа не создаёт.

Никаких Tailscale/TUN/default route/DNS/firewall изменений этот выпуск не делает.
Точная среда телефона ещё не сообщена; удалённый Mini App остаётся непроверенным.
Графические ответы бота работают независимо от маршрута телефона к серверу,
пока сам сервер и связь с Telegram доступны.
