## Что изменено

- Единое read-only разрешение основной должности для профиля, структуры, HR/team API
  и проекции доступа. История назначений исключает восстановление старого значения профиля.
- PRIMARY и ACTING разделены. Сроки назначений и штатных мест проверяются как `[from,to)`;
  неоднозначность, неизвестная должность, несовпадение подразделения и цикл блокируют разрешение.
- Руководитель и аттестация читают действующее штатное подчинение; legacy reporting
  остаётся fallback только для сотрудников без истории назначений.
- Company/team reads используют capabilities и действующее поддерево. Отключённый
  actor не получает доступ. Кадровый запрос связан с реальным текущим пользователем.
- Пересборка reporting сохраняет ручные решения, в том числе отличающиеся от штатного
  подчинения. Список коллег включает разные должности одного подразделения.
- CLI `local/ustar/cli/reconcile_organization.php` выдаёт JSON dry-run со stable IDs,
  источниками, конфликтами и расхождениями. Автоматического apply нет.

R10/R12 остаются in progress. Этот пакет не закрывает весь этап:

3. Завершить перевод остальных прямых читателей profile/reporting на общий контракт,

   optimistic checks и проверкой сохранности истории. Dry-run этого пакета ничего не применяет.
5. Выполнить сверку реальных кадровых данных перед переключением: новый resolver

награды, ручные роли и Moodle suspension при этой поставке не мигрировались.
