## Как попасть в нужный раздел

| Задача | Переход |
| --- | --- |
| Создать материал, загрузить файл, работать в Студии, настроить аудиторию | «Центр управления» → «Материалы» (`/local/ustar/materials.php`) |
| Настроить должности и маршруты | В центре управления → «Модели должностей» |
| Настроить условия Библиотеки, выдать доступ, создать мини-проверку | «Библиотека» → «Управление» (`/local/ustar/library_manage.php`) |
| Читать и проходить дополнительные материалы | «Библиотека» (`/local/ustar/library.php`) |

Новая кнопка «Центр управления» возвращает прежний переход администраторов из
«Базы знаний» в управление материалами. Внутри центра уже есть своя навигация,
поэтому вторая одинаковая ссылка туда не добавляется. На телефоне кнопка доступна
в полном меню «Ещё». У HR остаётся собственная панель. Обычным сотрудникам вход
в центр не выдаётся; в «Просмотр как» новая кнопка скрыта.

## Что видит сотрудник

| Вкладка | Назначение |
| --- | --- |
| Мои материалы | Полученные назначения, покупки, история изученных материалов и личные файлы, сохранённые из ленты |
| Каталог товаров | Разделы и карточки товаров, доступные по текущим правилам |
| Маркетплейс | Опубликованные предложения дополнительного обучения и их условия |
| Проверки знаний | Дополнительные проверки по темам, навыкам и товарам; процент и отметка |
| Обязательный маршрут | Переход в существующий маршрут сотрудника |

Материал может быть открыт своей аудитории, выдан по назначению, доступен за USCOIN
или после заданной точки маршрута. Назначение и покупка не расширяют аудиторию
исходного материала. Черновик сначала публикуют в редакторе материалов; предложение
Библиотеки имеет отдельный статус публикации.

Продажи после установки выключены. Пока администратор явно не включит их,
USCOIN за материал не списываются. Прохождение мини-проверки сохраняет отметку:
обязательная аттестация, прогресс маршрута, XP и награды остаются в своих контурах.

## Действия администратора и отдела обучения

1. В центре управления создайте и опубликуйте материал, задайте аудиторию.
   Для нового курса используйте существующую Студию; для обязательной аттестации —
   её обычную связь с маршрутом, а не мини-проверку Библиотеки.
2. Откройте «Библиотека» → «Управление». В «Условия доступа к материалу» выберите
   исходный материал, задайте название и описание, способ доступа и статус
   «Опубликовано». Нажмите «Сохранить условия».
3. Для назначения в блоке «Предоставить доступ» выберите сотрудника и материал.
   Руководитель видит сотрудников своей области управления. Выдавать доступ самому
   себе нельзя. В «История доступа» можно отозвать назначение.
4. Для проверки раскройте «Редактор проверок знаний». Укажите тему/навык/группу,
   число вопросов, порог и лимит попыток; заполните вопросы и 2–6 ответов с одним
   верным. Опубликуйте через «Сохранить проверку как новую версию».
   Для платной/назначаемой проверки отдельно настройте предложение Библиотеки.
5. Если нужны продажи, администратор раскрывает «Настройки продаж», выбирает
   диапазон цен и «Разрешить покупки за USCOIN». Исходный диапазон — 1–25.
   Возврат выполняется через «Вернуть USCOIN и закрыть покупку»; повторный возврат
   не должен начислять деньги ещё раз. Свой возврат выполняет другой администратор.

Товарные мини-проверки строятся по реальным данным карточки. Обновление карточки
попадает в очередь синхронизации; плановая сверка запускается каждые пять минут.
При недостатке достоверных вариантов вопрос пропускается. Старые попытки сохраняют
свой снимок вопросов и не переписываются после редактирования.

## Приёмка на реальных учётках

Подготовьте администратора, HR/HRD с нужными правами, руководителя и двух сотрудников
из разных областей управления. Используйте отдельные материалы с префиксом
«ПРИЁМКА», опубликованные только для выбранной аудитории. Запишите исходный баланс,
состояние обязательного маршрута и использованные учётки. Сотрудником входите
через отдельную сессию браузера: «Просмотр как» не заменяет проверку записи.

| Проверка | Действие | Ожидаемый результат |
| --- | --- | --- |
| Навигация администратора | Открыть главную и Библиотеку, затем «Центр управления» | Отдельные входы; открываются «Материалы», доступны прежние разделы, включая модели должностей |
| Навигация сотрудника | Повторить вход обычным сотрудником | Библиотека доступна, новая кнопка центра скрыта; прямые URL управления не дают чужих прав |
| Мобильное меню | Открыть главную и «Ещё» на телефоне | Ссылка центра доступна администратору, читаема и открывает правильную страницу |
| Бесплатный материал | Опубликовать источник и предложение для сотрудника | Видим и открывается; баланс не меняется |
| Аудитория | Попробовать открыть тот же материал сотрудником вне аудитории, в том числе по прямой ссылке/файлу | Доступ к содержимому закрыт; назначение не обходит аудиторию |
| Назначение | Установить «По назначению», проверить до/после выдачи и отзыва | До выдачи закрыт, после открыт и в «Мои материалы»; после отзыва закрыт, если нет другого действующего основания |
| Область руководителя | Выдать материал своему сотруднику и попробовать чужому | Свой доступ выдаётся; чужой сотрудник недоступен для назначения |
| Покупки выключены | Открыть платное предложение до включения продаж | Нет успешной покупки и списания USCOIN |
| Покупка и повтор формы | После отдельного включения продаж купить при достаточном балансе, повторить ту же отправку | Одно списание и один доступ; повтор формы не списывает ещё раз |
| Недостаточный баланс и изменённая цена | Попробовать купить без средств; затем отправить форму, открытую до смены цены | Покупка отклонена, лишнего списания нет; предлагается обновить условия |
| Возврат | Другим администратором вернуть покупку; повторить возврат | Сумма возвращается один раз; покупка закрывается, история остаётся |
| Дополнительная проверка | Открыть страницу, начать и завершить попытку, проверить повтор и лимит | Открытие страницы не создаёт попытку; отправка сохраняет результат, лимит действует, повтор не дублирует результат |
| Проверки и награды | Сравнить баланс, XP и маршрут до/после мини-проверки | Меняется только отметка проверки |
| Условие по точке маршрута | Проверить до и после прохождения заданной точки | Автоматическое условие открывается после точки; отдельное назначение/покупка остаётся самостоятельным основанием |
| Обязательное обучение | Открыть назначенную обязательную точку и завершить её штатно | Нет требования купить обязательный материал; native результат и переход сохраняются |
| Просмотр как | Открыть Библиотеку в режиме просмотра | Нет покупки, выдачи доступа и сдачи проверки от имени другого сотрудника |

Принять этап можно после выполнения нужных сценариев без потери результатов,
чужих доступов и повторных списаний. Зафиксируйте дату, роли, материал, ожидаемое
и фактическое поведение. При ошибке достаточно URL, шага и снимка экрана без паролей.
После приёмки архивируйте тестовые предложения и восстановите настройки продаж,
если они включались только для проверки. Историю попыток и операций не удаляйте.

## Установка навигационного исправления

Используйте отдельный `ustar-library-navigation-<tool SHA>.tar.gz`, а не повтор
установки Библиотеки. Установщик проверяет все 649 файлов исходного комплекта,
активный старый журнал, права и блокировки; меняет один файл layout и кратко
перезапускает только существующий web-контейнер. Владельцы, права и xattrs файла
сохраняются; схема, версии, результаты обучения, worker, egress и cron не меняются.

Без аргументов — автономный план. `--check` только читает: до установки `ready`,
после `active`. Применение: `--upgrade --acknowledge-outage`.
При незавершённой транзакции `--recover --acknowledge-outage` возвращает только
исходный layout и запускает web; БД не откатывается. После этого `--check` покажет
`rolled_back`, повторный `--upgrade` снова разрешён.

После исправления текущий контроль выполняйте новым `update.py --check`.
Старый6ee проверяет прежний layout, поэтому его отказ `application_source_changed`
после исправления ожидаем: это исторический установщик. Не удаляйте и не меняйте
старый журнал и не запускайте старый `--upgrade` поверх нового исправления.

Текущая поставка: `ustar-library-navigation-5131c552.tar.gz`, 118398 байт.
SHA256: `8ed2c915e3b984ef54e69dea056fd3e029357dc1bf9dc62463069c69fa7a0b79`.
Application `f89dde49cf22225653349fa519c00b1c0aaf1358`, tool
`5131c552ca5bc14ef1f1372640654696b1886577`.
[Профильный CI](https://github.com/cauf1l3d/ustarlms/actions/runs/41602749061/job/125805135631)
прошёл все 8 тестов, включая настоящий UID33/root и xattrs. Архив и все три члена
побайтно равны скачанному CI artifact13214802481; ZIP CRC и автономный PLAN_ONLY
проверены. Сохранённая копия скачана и также совпала побайтно.

Скопируйте архив в `/home/aduk`, выполните:

```bash
sudo bash <<'ROOT'
set -euo pipefail
umask 077
ustar_nav_archive=/home/aduk/ustar-library-navigation-5131c552.tar.gz
ustar_nav_dir=/root/ustar-library-navigation-5131c552
printf '%s  %s\n' \
  8ed2c915e3b984ef54e69dea056fd3e029357dc1bf9dc62463069c69fa7a0b79 \
  "$ustar_nav_archive" | sha256sum --check --strict -
test ! -L "$ustar_nav_dir"
install -d -o root -g root -m 700 "$ustar_nav_dir"
tar --no-same-owner -xzf "$ustar_nav_archive" -C "$ustar_nav_dir"
cd "$ustar_nav_dir"
sha256sum --check --strict SHA256SUMS
python3 -I -B update.py --check
systemd-run --no-block --unit=ustar-library-nav-20261103-01 \
  --property=Type=oneshot --property=TimeoutStartSec=180 \
  /usr/bin/python3 -I -B "$ustar_nav_dir/update.py" \
  --upgrade --acknowledge-outage
ROOT
```

До запуска ожидается `ready`. Этот запуск кратко остановит/запустит web. Затем:

```bash
sudo systemctl show ustar-library-nav-20261103-01.service \
  -p ActiveState -p SubState -p Result -p ExecMainStatus
sudo journalctl -u ustar-library-nav-20261103-01.service -n 30 --no-pager
sudo python3 -I -B /root/ustar-library-navigation-5131c552/update.py --check
```

После завершения ожидаются `Result=success`, `ExecMainStatus=0`, `phase=active`.
Одноразовая служба после успеха обычно `inactive/dead` — это нормально.
Если результат `refused`, передайте причину; не удаляйте блокировки и журналы.
При `recovery_required` используйте этот же новый скрипт с
`--recover --acknowledge-outage`, затем его `--check`. Если обновление уже active,
повторный `--upgrade` идемпотентен. Повторное создание той же systemd unit обычно
не требуется: сначала проверьте её результат.
