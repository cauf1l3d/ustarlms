# Виджет личного чек-листа в Telegram

Цель первого пилота — пройти короткий чек-лист целиком внутри одного сообщения. Сотрудник открывает «Чек-листы», выбирает назначенный на сегодня список, явно отмечает каждый пункт и отправляет ответы. Список показывает прогресс, сообщение подтверждает сохранение. Сотрудник может открыть пошаговую форму для комментария, длинного списка, черновика или клиента без поддержки виджетов.

Нативный виджет Bot API 10.4 поддерживает такой сценарий в личном чате. Mini App подходит для длинных форм, требует отдельного веб-контура. Обычный диалог остаётся подходящим для текста, фото и исправлений. Пилот запускается для одного или нескольких явно указанных сотрудников, до десяти. Для виджета беру новые списки из 1–5 коротких пунктов. Задачи остаются следующим сценарием после проверки виджета на устройствах сотрудников. [Bot API](https://core.telegram.org/bots/api#sendwidget), [ADR Connect](../../../context/decisions/0015-ustar-connect.md).

## Реализация и проверки

1. `bot_work.php` и `bot_checklist_widget.php` формируют карточку из текущего списка. Существующий токен действия связан с диалогом, датой, редакцией, набором пунктов и после отправки с ID сообщения. Сервис `checklist_service::submit` сохраняет тот же результат, что и пошаговая форма. Нативный тест проверяет явные отрицательные ответы, сохранённую историю, повтор, просрочку, чужое сообщение и конфликт с веб-формой.
2. `bot_widget.py` отвечает за статический HTML и формат запроса. Receiver принимает личный `widget_query` и передаёт типизированное расширение существующего `bot.update`. Проверяются ограничения формата, входящий чат и ответ Telegram. Python тестирует транспорт, несоответствие чата, отсутствие второго сохранения и отклонение Telegram с переходом в обычный сценарий. Браузер открывает тот же HTML с имитацией Telegram, проверяет прогресс, повтор и светлую/тёмную тему.
3. GitHub Actions проверяет два Moodle runtime и подписанный запрос между receiver и Moodle на синтетических данных. Установщик сверяет исходную пару приложения и worker, сохраняет состояние и поставляет оба компонента одним архивом. Владелец включает пилот по Moodle ID и проверяет результат в своём личном чате.

Данные карточки содержат только тексты коротких пунктов и непрозрачный токен. Выборы вводятся локально до нажатия «Отправить». Сервер хранит права, результат и квитанцию в существующих записях. Смена версии или привязки переводит открытый виджет в сценарий повторного открытия. Ошибка ответа Telegram после записи оставляет возможность безопасно запросить ту же квитанцию повторно.
