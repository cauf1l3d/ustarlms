## Что подтверждено

Владелец подтвердил прямое открытие SCORM после поставки51332a21. Точный вывод
server `--upgrade`/`--check active` не передан; это функциональная приёмка запуска,
а не новая инвентаризация хоста. Завершение и переход дальше не приняты.

В исходниках7ee2e45:

- `route_model::requirement_result(course)` ждёт `course_completions.timecompleted`.
  `studio_scorm_runtime::import()` создаёт SCORM с автоматическим completion, но
  не задаёт критерии завершения всего курса. Это выявленное расхождение; конкретный
  тип привязки проблемной production-точки из скриншотов не доказан.
- `route.php` GET читает модель без записи; фактическое продвижение требует
  защищённого POST/reconcile. Успех внутри SCO сам по себе не подтверждает этот POST.
- `scorm_route_return.js` подтверждает завершение по свежему серверному результату
  и смене надписи кнопки. В уже завершённом пакете последняя кнопка отключена;
  повторное открытие не создаёт нового события подтверждения.
- `route_continue::destination()` защищает от повтора той же CM-ссылки, но не
  обрабатывает `course_launch` как возможный возврат в ту же точку.
- Нынешняя модель связывает зачёт точки с немедленным переходом дальше. Отдельной
  политики окна повторения и ручного закрытия в Студии нет.

Ни один из этих статических выводов не является журналом браузера/сервера владельца.

## Предлагаемая логика

Одна политика опубликованной версии точки управляет всеми её учебными материалами.
Общая реализация на уровне маршрута покрывает существующие импортированные пакеты;
индивидуальная переделка каждого ZIP не даёт единой настройки в Студии.

1. Переход: сразу после выполнения условий; вручную кнопкой «Далее»; вручную или
   по окончании окна повторения. Старые точки сохраняют немедленное продвижение.
2. Повторный доступ: сохранять либо закрывать при переходе. До закрытия изученный
   материал можно открывать снова. В точке видны результат, повторное открытие,
   «Далее» и остаток срока. При закрытии предупреждение с отменой/подтверждением.
3. Срок: часы/дни, отдельно от срока действия результата `validdays`. В реализации
   принят отсчёт после первого подтверждённого выполнения условий точки — это
   предложенный вариант в утверждённом владельцем проекте.

4. Завершение SCORM: вернуться в маршрут; открыть следующую доступную активность;
   остаться в материале. В режиме удержания точки выбор «следующая» не обходит
   «Далее»/таймер: до закрытия доступна страница текущей точки. Промежуточные
   «Изучено — дальше» листают экраны; настройка относится к завершению всего курса.
5. Факт изучения, награда и история записываются однократно в существующие модели.
   Окно доступа не является второй моделью результатов/оценок. Повторный просмотр
   не меняет исходный зачёт; существующая политика переобучения сохраняется.
6. Серверный таймер закрывает доступ и продвигает последовательность без открытой
   вкладки; при открытой странице интерфейс обновляется по серверному состоянию.
   Непройденные обязательные аттестации/задания таймер не объявляет выполненными.
7. Закрытие проверяется сервером при повторном запуске и по старым адресам.
   Другие самостоятельные назначения того же материала сохраняют свои права;
   уже полученные браузером байты не могут быть удалены отзывом доступа.

## Границы реализации и проверки

- Сначала воспроизвести реальную цепочку импорт → публикация → курс/CM-точка →
  native SCORM completion → защищённый возврат → следующая точка. Исправить источник
  завершения, не объявляя произвольный Moodle-курс пройденным по первому SCO.
- Политика должна быть привязана к неизменяемой версии. Изменение в Студии проходит
  текущие actor/scope/sesskey/revision gates и создаёт новую публикацию.
- Отдельный access state допустим только как управление доступом; completion,
  assessment, rewards и renewal остаются в существующих канонических моделях.
- Native проверки: повторный просмотр и один зачёт/награда; ручной переход с
  отменой/подтверждением; timer без браузера; гонка POST/cron; старый URL; чужая,
  будущая и устаревшая точка; view-as; смена публикации; самостоятельное повторное
  назначение; обязательная аттестация; старые сценарии торгового зала.
- При изменении схемы нужны version bump, install/upgrade parity и новый оператор
  с учётом version guards cron/Connect. Поставку51332a21 и прежние операторы не менять.
- Новый архив только после применимых source/context/native/infra gates и проверки
  byte identity CI/скачанной сохранённой копии. Merge и agent SSH не разрешены.
