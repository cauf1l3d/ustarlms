## Результат для пользователя

В списке точки видны состояние сотрудника и состояние редакторской версии. Редактор выполняет три разных действия:

1. **Сохранить черновик** — сотрудник продолжает видеть текущую публикацию; изменения ещё не применяются.
2. **Опубликовать изменения** — новая версия проходит текущие проверки публикации; прежняя остаётся в истории.
3. **Скрыть шаг из маршрута / Вернуть шаг** — меняется видимость существующей точки без пересборки обучения и создания новой версии. Перед скрытием показывается область: вся семья или конкретная должность. Результаты/история сохраняются.

Форма содержит название, описание и понятный список «Что нужно пройти». Каждое требование — отдельная строка: материал/курс/активность/профиль/действие, название, обязательность и доступные ему параметры. Можно добавить/явно убрать строку. Несколько активностей и разные режимы материалов сохраняются точно, без выбора «последнего» и глобального checked.

Навыки, повторное обучение и SCORM-доступ находятся в дополнительных раскрывающихся секциях. Настройки, отличающиеся от стандартных, видны в кратком резюме; при ошибке соответствующая секция открывается. В скрытых секциях controls не disabled и не теряются при POST. SCORM-настройки применяются только к совместимым требованиям; несовместимый существующий набор показывается с объяснением, без молчаливой перезаписи.

Ошибка остаётся рядом с формой: понятная причина, выделенное поле, введённый текст сохранён. Конфликт двух редакторов требует сверки; stale revision не заменяется автоматически. Полное имя technical exception сохраняется только в допустимой диагностике, не в основном пользовательском сообщении.

## Рассмотренные способы

- Только исправить обработку checkbox/исключение: не устраняет потерю требований и неоднозначность draft.
- Отдельная команда видимости + lossless editor codec + компактный presenter: выбранный инженерный подход, сохраняет текущие доменные writers.
- Полная перепись маршрутов/новая модель: не нужна; нарушит соразмерность и усложнит миграцию истории.

## Границы реализации

ADR0004, route_model, route_commands, route_scope, completion/evidence/rewards остаются источниками правил. Каждый POST проверяет real actor/capability, view-as, sesskey, принадлежность route/point, должность, expectedmodified и блокировку в существующем порядке. Hidden/disabled UI не заменяет ACL. Общую точку из вкладки должности нельзя скрыть для всей семьи.

Для visibility не вызывать content publication validation и не менять requirements/version count; для publish проверять всё как прежде. Возврат показывает только существующую опубликованную версию, не публикует черновик автоматически. Внешние/непредставимые записи нельзя молча удалить: показать read-only или отказать с сохранением ввода.

Новый архив строится от установленного app719bf47c/toolaa61d595. Схема не меняется без доказанной необходимости и install/upgrade parity. Frozen installers сохраняются. После source/native/browser/операторной квалификации — новый архив/SHA/команды; установка владельцем отдельно.

## Приёмка

Скрытие и возврат: active меняется, версии/прогресс/награды не меняются; stale/foreign/inherited/view-as отказы атомарны. Черновик сохраняется и не скрывает published. Round-trip сохраняет полный ordered набор из нескольких cm/course/content/assessment/native/skill/previous_adaptation, required/completionmode/primary и текущую политику. Неподдерживаемые записи не исчезают. Desktop/Android/keyboard/zoom, без JS и при validation error доступны основные действия. Производительность измерена на representative staging; production нагрузка не создаётся.
