# Маркетплейс: отделы и исходные файлы

03.11.2026. Поручение владельца: «полностью скрыт с возможностью открывать по отделам с админки».
База — установленный navigation5131/applicationf89dde49, local/theme2026110200.

По умолчанию ни один отдел не включён. У сотрудника нет вкладки Маркетплейса,
прямой вход в витрину и невыданное предложение закрыт, покупка не выполняется.
Администратор видит витрину и может настроить доступ.

## Как открыть отделу

1. Администратором откройте «Библиотека» → «Управлять доступом и материалами».
2. Раскройте «Доступ отделов к Маркетплейсу».
3. Отметьте нужные отделы и нажмите «Сохранить доступ отделов».
4. Проверьте сотрудником выбранного отдела и сотрудником другого отдела в разных сессиях.

Если снять все отметки, Маркетплейс снова скрыт для сотрудников. Вложенные отделы
выбираются отдельно. Используются реальные IDs оргструктуры: перевод сотрудника,
удаление отдела и неизвестная должность не сохраняют старое разрешение.
В «Просмотр как» администратор видит права выбранного отдела, а не admin bypass;
менять настройки и скачивать исходники в этом режиме нельзя.

Выбор отдела открывает витрину, а не автоматически выдаёт платные материалы.
Условия каждого предложения сохраняются: бесплатно для аудитории, по назначению,
за USCOIN или после заданной точки. Разрешение продаж — отдельная настройка.
Ранее созданные предложения со свободным доступом остаются свободными для своей
аудитории после включения отдела; перед включением проверьте их условия в управлении.
Новые автоматические seed-предложения теперь draft/assigned: публикация и бесплатный
доступ требуют явного решения администратора. Существующие офферы и результаты
массово не переписываются.

## Исходные файлы

В читательской карточке товара убрана кнопка скачивания исходного Word/PDF.
Прямая pluginfile-ссылка на catalog_source также закрыта сотруднику, независимо
от бесплатного/купленного доступа к карточке. Редактор каталога сохраняет исходник
в административном редакторе. Изображения и содержимое веб-карточки доступны по
прежним правилам. Это ограничение выдачи исходников, а не защита от снимков экрана.

## Что сохраняется

«Мои материалы» с уже выданными/купленными материалами, обязательный маршрут,
родной SCORM/Quiz, каталог товаров, изображения, личные сохранения ленты,
балансы, попытки и история. Скрытие витрины не отзывает состоявшуюся покупку.

## Проверка после установки

| Сценарий | Ожидаемый результат |
| --- | --- |
| Обычный сотрудник, ни один отдел не включён | Вкладки нет; прямой tab=shop/open чужого предложения закрыт; покупка без списания |
| Администратор | Витрина и форма выбора отделов доступны |
| Включён один отдел | Маркетплейс виден только сотрудникам этого отдела |
| Сотрудник переведён в другой отдел | При новом запросе доступ определяется новым отделом |
| Сотруднику ранее выдан материал | Материал остаётся в «Мои материалы» и открывается по действующему праву |
| Word-исходник товара | Нет кнопки; сохранённая прямая ссылка сотруднику не выдаёт файл |
| Каталог и обязательная точка | Веб-карточка/изображение и назначенное обязательное обучение работают |
| Старая вкладка настроек | Конфликт revision отклонён; повторного сохранения поверх новых настроек нет |

## Обновление

Новый отдельный source-only successor принимает только установленный f89dde49
и активный журнал navigation5131. Проверяет все649 addon-файлов; меняет13 существующих
файлов, сохраняет UID/GID/mode/xattrs и частные настройки. Версии0200 и108 таблиц
не меняются, upgrade/schema/seed не запускаются. После перезапуска web штатный
purge_caches обновляет шаблоны: изменяется служебное состояние кешей, бизнес-данные
не откатываются. Восстановление возвращает исходные файлы с повторной очисткой кеша.
Старые операторы и журналы не изменяются. Текущий контроль после этого обновления —
новый update.py --check; предыдущий navigation checker описывает предыдущий payload.
