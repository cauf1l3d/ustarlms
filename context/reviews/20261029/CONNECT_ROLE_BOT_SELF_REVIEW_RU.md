# Connect2900 · авторская проверка перед поставкой

29.10.2026, Europe/Moscow. Приложение/worker `5cc02944e1059ba015afcc7c5e8068ca56c34a92`.
Кандидат согласованного установщика `99dbecaac7fe9c6bd2fa9e77349d336e448ca8a6`.
Это повторный проход автора по требованиям и опасным переходам, без субагентов;
не независимое ревью и не приёмка реального Telegram владельцем.

## Проверенные границы

| Граница | Реализация и проверка |
|---|---|
| Единая Академия | PHP адаптеры вызывают существующие task/checklist/staffing/grading/adaptation writers. Три новые таблицы содержат только диалоги, действия и квитанции; Python не хранит кадровую или учебную модель |
| Actor, роль и область | Привязка, активная кадровая учётка, capability и текущая область проверяются заново. Ввод не принимает userid/роль/URL; сохранённые ответы дополнительно несут внутренние object guards. Отозванная связь не открывает старые квитанции |
| Чувствительные команды | Bot bridge подготавливает команду. Native страница требует независимую cookie-сессию того же пользователя и POST/sesskey; cookie-free bridge, другой actor, View-as и logged-as не выполняют подтверждение |
| Повторы и конкуренция | Существующая identity-блокировка, optimistic revision, canonical locks/row locks и квитанция в одной бизнес-транзакции. Повторная отправка при неизвестном результате не выполняется автоматически |
| Фотографии | Разрешение private draft выдаётся до скачивания; размер фактических bytes ограничен512KiB, PHP проверяет MIME/размерность, File API владеет файлами. Произвольные пути/URL не принимаются. Черновики удаляются без удаления канонического отчёта; независимое подтверждение старой заявки сохраняет более новую форму |
| Telegram представление | Текст экранируется, таблицы/прогресс и кнопки ограничены контрактом; длинные формы/списки разбиты на страницы. Допустимы только личные текущие сообщения/кнопки; пересылки и иной чат не выбирают actor |
| Переход от пилота | Старые link/ACK ключи и ACK cutoff сохранены, bot-only ключ отдельный. Широкая доставка требует явного профиля и личного opt-in, начинается с нового cutoff. Старые отметки «Принял» сохраняют первоначальное время |
| Установщик | Приложение2803→2900 с парной копией/повтором/recovery, затем согласованный worker/profile. Незавершённое включение возвращает прежний runtime; после публикации recovery сохраняет новые бизнес-записи. Старые установщики побайтно неизменны |

## Исправленные существенные находки

1. CLI проверка пыталась подменить независимую браузерную авторизацию. Защита оставлена;
   положительный сценарий перенесён в настоящий HTTP login/GET/POST с sesskey.
2. Site administrator не является кадровым сотрудником. HTTP fixture исправлена на
   активную обычную HRD-учётку; ограничение production не ослаблено.
3. Условие ACK зависело от старого списка единственного пилотного получателя.
   Явный linked/opt-in профиль поддерживает ACK без неявного включения получателей.
4. Подтверждение старой native-команды очищало новую форму. Сравнение revision
   сохраняет более новую форму и её приватную фотографию.
5. Обязательный `file_size` отвергал допустимые Telegram фото. Необязательные поля
   поддержаны; фактический размер по-прежнему ограничен и сверяется с заданными.

## Практические ограничения

Первый пароль нового сотрудника, полные курсы/Quiz/SCORM/Студия, старые загруженные
в браузере фотографии и исправления итогового чек-листа остаются в native Академии.
При внешнем SSO/MFA/password-expiry рабочие операции не обходят политику входа.
Mini App, публичный Academy HTTPS, Bitrix/WhatsApp и новая политика CEO-эскалаций
этим выпуском не включаются. Сервисный Moodle site administrator не участвует
в кадровой привязке; USTAR роли назначаются обычным рабочим учёткам.

Окончательный CI, побайтная проверка архива и факт owner deployment фиксируются
отдельно. На момент этого авторского прохода production подтверждён только на2803,
worker6c56. Real Telegram/role acceptance после установки выполняет владелец.
