## Изменение

Для добавления на домашний экран используется второе изображение пользователя
`image(20261002-124028).png`, 1254×1254, полностью непрозрачное.
SHA256 исходника: `eb1563616fbb81168c514e2518bd71aa62080b50550c77ac2b7576dd52bf6027`.
Рисунок, золотая стрелка и рамка сохранены: выполнено только уменьшение Lanczos
и экспорт RGB PNG в 180, 192 и 512 пикселей.

`app_icon.php` отдаёт готовые PNG вместо ресэмплинга старой иконки через GD.
180×180 подключён как apple-touch-icon с явным размером; 192 и 512 — через
существующий PWA manifest с purpose=any. Идентификатор, scope, start_url и режим
standalone сохранены. Это не отдельный maskable-дизайн: форма отображения
внешних углов определяется платформой. Версия адресов и worker cache обновлена
до `2026100203`; личные страницы по-прежнему не кэшируются worker.

Старый `ustar-app-icon.png` остаётся как ранее используемый контент и fixture;
установочная иконка больше его не читает. Frontend-прототип не является
production Moodle и в эту поставку не входит. Изменений схемы и прав нет.

## Проверки

Локально: визуально проверен PNG 180×180; размеры, непрозрачность и PNG-формат
всех трёх файлов проверены; shell syntax, diff и структурные source checks.
PHP/runtime и установка на устройство локально не выполнены.

Полный CI кандидата должен пройти перед выдачей SHA для установки. В реальном
HTTP smoke изолированного Moodle проверяются versioned URLs из manifest,
apple-touch-icon из фактического HTML логина, точное совпадение HTTP-ответов
с тремя файлами, тип PNG, размеры, отсутствие Set-Cookie без авторизации
и отказ 400 на неподдерживаемый размер. Остальные runtime/regression проверки
релизного gate сохраняются. Итоговый CI SHA и результаты фиксируются в PR.
CI не доказывает внешний вид установленной иконки на конкретном iPhone.

## Установка и приёмка

`scripts/release/deploy_app_icon.sh FULL_REVIEWED_SHA` допускает только PR74
с версиями `2026100202:2026100201` и полным совпадением исходников. До замены
создаётся согласованный backup PostgreSQL, кода и moodledata. После upgrade
проверяется полный manifest, права чтения, публичный HTTP и побайтное совпадение
ответов иконки для 180/192/512 с кандидатными файлами.

После `DEPLOY_SUCCESS=YES`: открыть Академию в Safari, удалить старый ярлык
и добавить снова через «Поделиться» → «На экран Домой». Проверить новую
золотую иконку и запуск Академии. Уже сохранённый ярлык может продолжать
использовать ранее выбранную ОС картинку; обновление URL не является гарантией
его немедленного обновления. Production deployment и проверка на устройстве
подтверждаются отдельно пользователем. При отказе после замены файлов
использовать согласованный backup, не откатывать только код после upgrade.
