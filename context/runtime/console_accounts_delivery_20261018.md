## 2. Проверить журнал и реальные запросы

После обновления страницы раздел журнала служб использует `events_status`, независимо от журнала запросов. При `events=ok` и пустом списке должно быть понятное сообщение об отсутствии подходящих событий за5мин; оно не означает, что весь journalctl пуст. При requests=`source_empty` остаётся честное отсутствие измерений, а не ошибка настройки событий и не нулевые RPS/p95.

Диагностика выше сравнивает `direct` (источник сейчас), `snapshot` (последний снимок сборщика), возраст снимка и только размер/владельца/mode числового лога. Не выводит сырые сообщения, URL или IP, не создаёт HTTP-запросы и не перезапускает Apache. Открыть несколько обычных страниц самой Академии; после цикла сборщика проверить requests/RPS/p95/4xx/5xx и покрытие5мин. Неполное окно явно помечено. Если состояния расходятся, прислать безопасный JSON диагностики; не присылать raw logs или конфиги.

## 3. Создать учётку сисадмину

Войти владельцем → «Пользователи» → «Создать пользователя». Логин латиницей, пароль не короче14символов. Для штатных разрешённых операций выбрать «Оператор», для чтения — «Наблюдатель»; «Владелец» управляет доступом. Подтвердить своим текущим паролем и TOTP, если подключён. Передать пароль сисадмину приватным способом. Проверить вход новой учётки; viewer/operator не должны управлять пользователями. Смена роли/пароля и блокировка отзывают сессии; последнего владельца нельзя отключить или понизить, себя-владельца — тоже.

## 4. Привязать личный Telegram

Сисадмин входит **под своей** учёткой → «Мои уведомления» → «Мой Telegram» → создать код. Отправляет показанную `/link КОД` существующему USTAR-боту лично, не пересылая чужое сообщение; затем «Обновить статус». Код одноразовый,256-bit, действует10мин; в store хранится его хеш. Проверить показанный numeric Telegram ID и ответ бота. Тот же Telegram нельзя связать с двумя учётками. Не публиковать код, bot token или пароль.

Старый root-configured bootstrap Telegram allowlist сохраняется отдельно. Блокировка/отвязка UI-пользователя отзывает его динамическую привязку, но не редактирует исходный root allowlist. Поэтому владельца, уже внесённого при setup, нельзя считать полностью исключённым из бота одной UI-отвязкой. При недоступном настроенном notifier изменение доступа отклоняется, а не подтверждается ошибочно.

## 5. Настроить личные алерты

«Мои уведомления»: включить доставку, выбрать проверки и состояния «Внимание»/«Авария»/«Нет данных». CPU1..100%, доступная RAM1..99%, удержание0..3600с; повтор15..1440мин; тихие часы HH:MM и IANA timezone, например Europe/Moscow; отдельно уведомление о восстановлении. Сохранение подтверждается текущим паролем/TOTP. Это персональные настройки текущей учётки, не всех получателей.

Старый backlog не отправляется пачкой после тихих часов: worker заново оценивает состояние. Повторы считаются от фактической доставки. Пропуск/устаревшее измерение не продолжает CPU/RAM hold. Свежие данные и завершённая привязка обязательны. Сохранённые настройки/active service не равны подтверждению доставки Telegram: нужен ответ получателя. Не имитировать отказ продакшена ради теста. Для проверки личного порога можно временно задать условие по уже наблюдаемой нагрузке, дождаться периода/hold, убедиться в получении и сразу вернуть рабочие значения; доставка зависит также от тихих часов и выбранных статусов.

## 6. Как замечать полное отключение сервера

[Схема](../../server-console/HOST_LOSS_20261018.md) готова, интеграция **не активирована**. Без собственного второго сервера подходит внешний managed heartbeat: server1 посылает исходящий HTTPS раз в60с, внешний сервис тревожит при пропуске с grace180с. Порт пульта наружу не открывается, root bot token сервису не передаётся. Отдельные сигналы хоста и свежего локального HTTP помогают отличить проблему приложения от исчезновения пути.

По одному пропавшему сигналу нельзя отличить питание, зависшую ОС, офисную сеть, провайдера или недоступность наблюдателя. Для уточнения можно использовать уже работающий офисный ПК/NAS и телеметрию роутера/UPS. Пока не выбраны сервис и секретные ping URL локально, observer честно остаётся «не подключён». Нет собственного второго сервера — возможно; нет никакого независимого наблюдателя — невозможно заметить молчание выключенного хоста извне.
