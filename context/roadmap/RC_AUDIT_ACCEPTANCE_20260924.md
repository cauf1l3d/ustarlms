# Реестр приёмки инженерного аудита — релиз-кандидат (24.09.2026)

Источник: переданный владельцем `USTAR_ENGINEERING_AUDIT_REFACTOR_PLAN_20260920(1).md`, раздел 7. Ниже без изменений сохранены формулировки всех 60 требований. Разделы 1–6 и 8–14 исходного аудита также обязательны. Наличие кода или успешная проверка исходников не означают приёмку работающей системы.

**Условие приёмки:** Для каждого номера нужны решение о реализации либо обоснованном исключении из продукта, ссылка на изменение, доказательства выполнения критериев и итоговая проверка владельца. Пока ни один пункт не принят. Замечание № 4 баг-репорта оставлено на проверку владельца; изменение формы на сервере не доказывает исправность сервиса сброса.

**Как пользоваться таблицей:** Номер в первом столбце связывает требование с исходным аудитом. В третьем столбце указано, что уже известно о его выполнении; «Приёмка не завершена» не означает, что к пункту не приступали. Принимать строку можно только после проверки соответствующего сценария на зафиксированном SHA и записи результата. **P0** — защита до выпуска затрагиваемой функции; **P1** — основная работа рефакторинга; **P2** — последующее упорядочение. Обозначения из аудита: **К** — подтверждено чтением кода, **Т** — воспроизведено отдельной пробой, **Р** — риск, который требуется проверить или согласовать. Они описывают основание замечания, а не факт приёмки.

**Исторические доказательства и квалификация (C09, E05; только исходники):** При чтении «на дату» учитываются события не позднее указанного момента; более поздние факты отклоняются. Публикация стандарта должности — отдельное действие. Отсутствие опубликованного стандарта отличается от отсутствия подтверждённого уровня навыка. HR может внести или отозвать оценку руководителя, привязанную к опубликованной версии стандарта; новая версия требует новой оценки. Завершение курса само по себе не подтверждает уровень навыка. Перенос исторических доказательств, проверка в браузере и итоговый тест Moodle с БД ещё не выполнены.

**Поиск (E07; только исходники):** Совпадения по курсам, материалам и людям выбираются постранично до набора достаточного количества результатов, разрешённых правами пользователя; область команды ограничивается в SQL до пагинации. Ожидающая подтверждения или неактивная учётная запись не получает результатов. Ссылки на должности, навыки и сотрудников ведут к соответствующим объектам. Поиск на больших объёмах и права конечного получателя ещё требуют проверки в браузере и рабочей среде.

**Приватный развивающий опросник (C15; только исходники):** Открытая форма хранит ID опубликованной версии и серверное время открытия. Отправка отклоняется после публикации новой версии или спустя два часа; сохраняется фактическое время открытия. Результаты остаются приватными и не становятся подтверждением квалификации. Рабочий сценарий и гонки при публикации ещё не проверены.

**Списки сотрудников (E06; только исходники):** HR API возвращает точные значения `total`, `offset` и `hasMore` после фильтрации по сотрудникам и подразделению. Экран HR во фронтенде получил переходы между страницами и не фильтрует уже обрезанную выборку. Подсчёт пока просматривает подходящие учётные записи: нужны измерения числа запросов и времени ответа на объёме production. Сводка руководителя показывает неполную выборку вместо выдуманного итога.

**Экономика (C06; только исходники):** Общий сервис операций USCOIN отклоняет начисления и списания для тестовых, сервисных и иных нерабочих учётных записей, включая вызовы из маршрута и CLI. Отмена исторического списания остаётся возможной. Записи тестовых аккаунтов в существующем реестре требуют отдельной инвентаризации и решения; награды за игры и другие способы начисления, а также работающий сценарий ещё не приняты.

**Каталог (C14; только исходники):** Поиск, страница каталога и выдача файлов используют согласованную проверку доступа. Давнее прохождение обучения не открывает каталог пользователю с ожидающим или приостановленным статусом; администраторы сохраняют авторский доступ. Проверки в браузере для ожидающего, допущенного, отозванного и авторского аккаунтов ещё открыты.

**Расчёт квалификации (E05, E08; только исходники):** Экран руководителя загружает решения об оценке навыков и их отмены пакетно по опубликованным версиям, а не отдельным запросом для каждого сотрудника и навыка. В пределах версии действует последнее решение. Число запросов, задержка, индексы и точность на реальных данных ещё не проверены.

**Подтверждение материала (D01; только исходники):** Событие изучения точки маршрута обязано указывать открытую версию материала; вызов без версии отклоняется, включая диагностическую CLI-команду. Публикация новой версии между открытием и подтверждением не приводит к ложному зачёту. Переход между версиями в браузере и старые факты ещё требуют проверки.

**Блоки оргструктуры (B13; только исходники):** HR может создавать и переименовывать блоки без изменения их ID; `company_hierarchy` выводит заданные названия и новые блоки. Именные эвристики руководителей и ассистентов и модель прав ещё требуют архитектурного согласования. Переименование блока не переписывает назначения сотрудников; связи с должностями и подчинением нужно проверить в рабочей среде.

**Кадровые заявки руководителя (B04; только исходники):** Список заявок использует все ID подразделений из `organization_model::manager_scope`, а не только первый корневой отдел. Это исправляет видимость заявок дочерних подразделений, но ещё не доказывает совпадение областей доступа для решений, отчётности, поиска, API и временно исполняющих обязанности руководителей.

**Срок действия штатного места (B06; сверка исходников):** Текущий `organization_model::staff_place($id, $now)` уже проверяет `active`, `effectivefrom` и `effectiveto`; `occupant_for_place` вызывает его до выбора назначения. Исходная формулировка аудита сохранена для прослеживаемости, но утверждение об отсутствии проверки дат устарело для этой ветки. Границы дат, будущие и истёкшие места, а также все операции записи ещё требуют проверки в рабочей среде.
