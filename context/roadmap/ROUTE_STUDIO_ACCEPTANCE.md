# Приёмка студии маршрутов

Для R02/R03/R09. Основа: существующий ADR-0004, одна физическая parent point и scoped override. Это список ещё не выполненных проверок.

## Целевой сценарий HR

Выбрать подразделение/семью → увидеть общий маршрут и опубликованную версию → добавить или изменить точку → выбрать применимость → увидеть предварительный результат для должностей → опубликовать → открыть тот же состав в кабинете тестового сотрудника. Для локального изменения явно выбрать «Изменить для этой должности»; «Вернуть общее» сохраняет историю.

У HR видны черновик, текущая публикация и различия. После ошибки форма сохраняет введённые данные. Успешное сообщение выдаётся только после commit всех обязательных частей. Пользователь не вводит CM/DB ID вручную в обычном сценарии.

## Один resolver для всех потребителей

`route_scope` разрешает состав по family + position + опубликованным версиям. Его результат используют studio preview, `for_user`, `read_only_snapshot` и проверка launch. Он:

- оставляет один общий шаг, если нет действующего override;
- заменяет его одним подтверждённым override конкретной должности;
- сохраняет локальные точки только для их области;
- не показывает proposed/reverted как действующие override;
- обрабатывает отсутствие scope старой точки отдельно от отозванного scope;
- возвращает stable logical identity для completion/rewards;
- не материализует копии всему семейству при простом просмотре или публикации;
- одинаково объясняет причины отсутствия точки: draft, inactive, scope, archived.

## Матрица проверки

| ID | Действие/условие | Ожидаемый результат |
|---|---|---|
| ST01 | Создать черновик | HR видит; сотрудник не видит; нет enrolment/progress/reward от preview |
| ST02 | Опубликовать корректную общую точку | Все confirmed позиции семьи видят одну логическую точку/версию |
| ST03 | Добавить unique point одной должности | Видна только этой должности; соседняя не получает доступ |
| ST04 | Изменить common point из position-view | Явно создаётся scoped override с sourcepointid; parent не изменён |
| ST05 | Изменить существующий override | Новая версия только этой должности; старые версии/факты сохранены |
| ST06 | Вернуть общее | Scope получает reverted по ADR; история остаётся; другой отдел не получает override |
| ST07 | Редактировать parent после override | Общие потребители получают новую публикацию; override не перезаписан |
| ST08 | Proposed scope | Не даёт сотруднику видимость/launch; HR видит предложение и его статус |
| ST09 | Пустой/несуществующий source или только неподдерживаемые условия | Publish отклонён на сервере; поля формы сохранены |
| ST10 | Draft после published | Сотрудник продолжает видеть последнюю действующую публикацию |
| ST11 | Два редактора, одна revision | Первый commit успешен; второй получает conflict; потери версии/метаданных нет |
| ST12 | Искусственный сбой INSERT version или policy inheritance | Откат всей команды; прежняя публикация неизменна |
| ST13 | Reorder drag и кнопками с клавиатуры | Один сохранённый порядок; refresh воспроизводит его; stale reorder отклонён |
| ST14 | Archive/restore | История completion/reward не удалена; доступ соответствует статусу |
| ST15 | Прямой POST чужого pointid/family/position и неверный sesskey | Отказ; скрытая кнопка не единственная проверка |
| ST16 | Return/upload material | Опубликованный доступный материал привязан в одну новую версию; нет половины сохранения |
| ST17 | Просмотр supervisor/view-as | Нет grants, completion, enrolment и assessment mutation |
| ST18 | Сравнить preview, employee, manager snapshot | Одинаковая применимость/публикация; snapshot может ждать sync, показывает timestamp свежести |
| ST19 | Renewal keep/force/expiry, remediation | Прогресс следует политике; ретейк не теряет старое evidence и не дублирует награду |
| ST20 | Mobile/desktop, zoom 200%, keyboard, dark/light | Форма и controls читаемы; нет недоступных действий; focus и feedback видны |

## Где менять

- `moodle/local/ustar/route_studio.php`: POST сделать тонким, одинаковая server validation всех действий, без старого несогласованного target lookup.
- `classes/route_scope.php`: общий resolver и ясные состояния, без неверного fallback для отменённых override.
- `classes/route_family.php`: отделить legacy materialisation от действующих команд; сохранить только проверенный compatibility path.
- `classes/route_model.php`: атомарное сохранение версии; shared resolver; явная reconciliation-команда отдельно от read-only.
- `templates/route_studio.mustache`, `amd/src/route_studio.js` и AMD build: действия, сохранение порядка, error/conflict и понятное состояние публикации.
- `db/install.xml` / `db/upgrade.php`: только необходимые ограничения/поля, parity install/upgrade на PostgreSQL.

## Релизный результат

К задаче приложены SHA, перечень миграций, DB integration результаты ST01–ST19, браузерные доказательства ключевых сценариев и ST20, manifest артефакта, rollback. Существующие role/assessment/materials проверки не ухудшились. Нет зависимости от жёстко заданных production ID в новых фикстурах. Появление кнопок в шаблоне не считается готовой студией.
