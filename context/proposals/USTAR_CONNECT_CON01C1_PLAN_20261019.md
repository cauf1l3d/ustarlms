## Concrete contract

- Python3.12 standard library. Fixed HTTPS api.telegram.org methods getMe/getWebhookInfo/getUpdates/sendMessage only; CA/hostname checks, no redirects/ambient proxies. Optional explicit HTTP CONNECT proxy must be literal loopback with port, no credentials/path/query. Bot API requires token in its upstream path; never print URL/request/traceback/raw error bodies. No browser/admin credential reuse.
- Startup checks getMe bot ID against configured token tenant and configured username; active webhook/401/409 stop, never delete webhook or pending updates. For personal launch require explicit onboarding_enabled=true and has_main_web_app=true. Default disabled replies with honest preparation message. Main Mini App URL must separately be configured/accepted in BotFather; flag alone does not prove BFF origin.
- getUpdates offset>=0,limit50,timeout25,allowed_updates=[message]. Validate bounded array/strict increasing update IDs before processing. Existing unwanted update types may still arrive and are ignored. HTTP timeout35, bounded2MiB response/16KiB outgoing request. Numeric IDs exclude bool/float/string; subject from message.from only, private chat.id must equal from.id, is_bot=false, no forward/sender_chat/via_bot/business/guest contexts. Only exact entity-marked /start,/academy,/help, optionally @configured_bot; no arguments, free text/password/profile storage or business commands.
- /start and /academy request launch.create with provider/tenant/subject derived from verified Bot API update. Return ticket must be canonical ul1_, future expiry<=600s. Send a private plain text message and inline URL button https://t.me/<verified_bot_username>?startapp=<ticket>. Ordinary web_app URL parameters are not substituted for signed start_param. Future signed exchange still checks same provider subject.
- Existing launch is also bound to **bridge key ID**. Receiver create and BFF exchange must use the same configured private provider service key ID/secret. Do not split into incompatible launch-only/exchange-only key IDs without a separate protocol migration. This service credential remains provider scoped and is not an Academy actor; bot token is separate. Explicit operation allowlist for current shared worker: launch.create,launch.exchange,entry.revoke,registration.options,registration.submit,registration.status; don't dynamically enable all OPERATIONS.
- Local SQLite transport journal is expressly allowed by RFC; it stores tenant binding, offset, last successful poll, cooldown/gap flags; per update ID, identity hash, kind,state,time,reason,provider message ID. No raw message/profile/password/bot token/service key/launch ticket/URL, and no copied employee state. Keep receipts7days with bounded prune500/poll, cap10000rows and SQLite64MiB. forget_identity clears hash but preserves live dedup barrier. Provider accepted is not user read or business resolution.
- Require existing private0700 same-owner non-symlink state directory; SQLite/lock0600 regular single-link files, exclusive flock across processes, durable FULL SQLite transactions. Separate from console DB/UID. Wrong bot tenant or unknown schema fails closed. Don't repair foreign ownership or unsafe files. Controlled test-only temporary dirs are fine.
- Persist received/creating/sending before external work, terminal state+offset in one SQLite transaction. Restart converts incomplete rows to uncertain and advances their offset, never automatically reissues a ticket/message. Missing last response can mean delivered; user sends new /start. Exact provider429/403 rejection is distinguished from timeout/5xx uncertainty. Retry-After delays polling and new sends globally; no automatic resending launch commands. This slice does not implement canonical notification outbox delivery.
- Stable next offset confirms only durably processed updates. After successful empty poll use offset0 for next poll: remote has acknowledged the prior offset, and this avoids assuming forever-monotonic IDs after a week of inactivity. After24h downtime reset local polling offset0 and mark possible history gap before any request; don't claim full history. Never negative offsets or drop_pending_updates. Recent replay IDs remain deduplicated even after offset reset.
- Launch commands must be fresh<=120s/skew30; per identity max3 launch attempts/600s, fixed global polling batch cap50. Stale/unsafe commands advance only a durable ignored receipt. On unknown/malformed batch, abort before advancing offset. Polling transport failures use bounded exponential backoff+jitter, persisted across restart; rate limit honors validated retry_after<=86400. 401/409 require intervention, no takeover loop.
- CLI loads owner-private JSON config and secret files, --run required for any network/receive/send, default local validation only. Test fakes are dependency boundaries; no real bot traffic during development. CLI emits fixed status/reason/aggregate health only. Long waits are interruptible. No systemd install/activation, networking/edge or BotFather mutation in this slice.
- Shutdown checks before polling and between events; already-running bounded operation may finish, then stop. Fetched unprocessed tail is not acknowledged. Freshness is checked using current time after long poll and before every event, not one timestamp for whole batch.
